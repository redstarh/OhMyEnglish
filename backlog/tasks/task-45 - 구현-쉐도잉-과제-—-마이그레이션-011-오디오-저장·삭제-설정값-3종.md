2. **행마다 `conn.execute` 를 유지함.** 시드가 1행이라 `executemany` 가 아끼는 것이 없고 `SEED_SCENARIOS` 도 같은 형태임.
3. **`migrate.py` 를 시드 자리로 유지함.** 마이그레이션 SQL 에 넣으면 파일명 추적 때문에 재시드가 불가능해지고, 별도 스크립트는 새 실행 경로를 만듦. `SEED_SCENARIOS` 선례와 같은 자리임.

5. **테스트 두 건을 합치지 않음.** `..._satisfy_the_schema`(CHECK 통과)와 `..._does_not_duplicate_clips`(멱등)는 후자가 전자를 포함하지만, **실패 시 원인 구분이 됨** — 전자만 red 면 CHECK 위반, 후자만 red 면 멱등 결함임.

**진입점 결합을 여기서 재지 않은 이유**: `tests/conftest.py` 의 `seed_shadowing_clips` 픽스처가 **자기가 만든 행 밖의 클립이 있으면 실패**함(누출을 시끄러운 실패로 바꾸는 장치). 시드 행을 커밋하는 테스트를 두면 그쪽이 조용히 깨짐. 그래서 이 파일은 `db_conn`(롤백)만 쓰고 선택 로직 자체는 그 픽스처가 계속 소유함.
