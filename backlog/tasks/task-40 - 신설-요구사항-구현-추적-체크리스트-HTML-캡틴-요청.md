## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
2026-09-12 완료 — docs/requirements-tracking.html 을 만들고 README 핵심 문서에 링크했음.

⛔ 형태를 사용자가 골랐음(선택지 셋 중 ①「수기 판정 + 근거 링크」). 나머지 둘은 ②「기계 생산 + 수기 판정 분리」 ③「범위를 슬라이스 1·2 로 자름」이었음. 고른 안의 대가를 산출물이 명시함 — 갱신은 사람이 하므로 다음 구현에서 함께 고치지 않으면 조용히 틀림.

⛔ 형식 규약과 성질이 다르다는 것을 먼저 갈랐음. docs/ops/status-report-convention.md 는 「만든 뒤에 고치지 않는」 스냅샷 보고서용이고 이 산출물은 갱신되는 추적표임 — 형식만 참고하고 그 차이를 머리말과 README 에 못박았음.

담은 것: §7 매핑 표(7절) · §10(13행) · §11(16행) · §13(12행) · §14·§15(합쳐 12행) · 고아 목록 · 갱신 규약 · 「이 표가 말하지 않는 것」. 표 6개 · 행 73 · 510줄. HTML 파싱 오류 0건 · 닫히지 않은 태그 0건(직접 파서로 확인).

⛔ 판정을 추측으로 채우지 않았음. 번호 요구사항 64건 기준으로 미판정 3건(R10-5 · R10-8 · AC10-4)이고 셋 다 「실물 음성 세션의 계측이 있어야 닫힌다」를 같은 행에 적었음. 미충족은 1건(AC11-5)이고 캡틴 결정 2026-09-04 로 이월된 것임. 배지 수를 기계로 세어 KPI 와 대조했음.

이 표가 만든 발견 셋.

1. ⛔ §7 의 세 절이 번호 요구사항을 «하나도» 갖지 못했음 — Voice Control · Business English · Shadowing. 즉 §10~§15 만 훑으면 그 셋이 보이지 않음. 그래서 ⛔ 충족률을 숫자 하나로 세지 않았음(분모가 정의되지 않음).
2. ⛔ 고아 6건 — R14-3 · R14-6 · AC14-2 · R15-2 · R15-4 · R15-6 이 PRD 밖에서 아무도 언급하지 않음. 여섯 다 코드 근거로 충족 판정을 받았으므로 「구현 없음」이 아니고 «추적의 구멍»임.
3. R15-5 를 부분으로 내렸음 — _HISTORY_SQL 이 learned 와 analyzed 를 가르는데 daily_error_summary 가 2026-09-11 에 생겨 그 이전 날짜에는 「학습은 했는데 요약이 없다」가 실재함(그 설계서 §6 미결 ⑴).

⛔ 내 단정 둘이 틀려 고쳤음. ① 고아의 원인을 「§14·§15 가 설계서를 갖지 않았다」로 적었는데 §15 는 전용 설계서를 가짐(docs/design/2026-09-11-streak-and-history-design.md). 실제 원인은 그 설계서가 인용한 ID 가 셋뿐이라는 것임 — 설계서의 존재가 추적을 만들지 않고 ID 인용이 만듦. ② §15 소유를 TASK-3 으로만 적었는데 코드 주석이 TASK-107 을 지목함.

⚠️ 자기 참조 함정을 남겼음 — 이 문서 자신이 이제 그 ID 들의 두 번째 언급이므로 고아를 다시 셀 때 requirements-tracking.html 을 제외해야 함. 세는 명령을 그 절에 적었음.

부수로 README 의 낡은 두 줄을 고쳤음(AC#2 가 그 색인을 요구함). PRD 를 「정본 v1.1」로 적고 있었는데 실제는 v1.4 임. 그리고 handoff/HANDOFF.md 로 링크하고 있었는데 그 파일이 없음 — 갈래별 넷으로 갈렸고 그 목록과 「자기 갈래만 읽는다」를 적었음.
