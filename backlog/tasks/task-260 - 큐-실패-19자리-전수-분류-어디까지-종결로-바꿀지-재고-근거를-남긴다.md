## Implementation Notes

<!-- SECTION:NOTES:BEGIN -->
조사 결과 (2026-09-20 · 이 세션이 직접 셌음). report_failure 호출 19자리를 질문 둘로 갈랐음 — 입력이 바뀔 수 있는가 · 모델 호출 앞인가 뒤인가. AC#2 판정: 추가로 바꿀 자리는 «없음». 근거 셋. ⑴ 모델 호출 «뒤»에 걸리는 입력 불변 실패는 ScenarioNoStage 하나뿐이고 그것은 TASK-259 에서 이미 종결로 바꿨음. ⑵ 모델 출력의 계약 위반 다섯 자리는 「다른 표본이 지킬 수 있다」가 참이라 재시도가 맞음. ⑶ PLAN_NO_FOCUS_CANDIDATES 는 호출 전이라 비용 0이고 입력이 실제로 바뀜 — 같은 몇 분 안에 다른 분석 job 이 끝나면 복습·만성 후보가 생김. 종결시키면 재시도가 값을 하던 경로를 죽임. ⑷ 대상 없는 job·사라진 세션·라우팅 누락 자리들은 호출 전이고 analysis_jobs_target_matches_job_type CHECK 와 FK cascade 가 구조적으로 막아 도달이 거의 불가능함 — 바꿔도 잴 값이 없음. AC#3: 분류 규칙을 jobs.fail_terminally 의 docstring 에 적었음(그 함수를 쓰려는 사람이 읽는 자리임). ⚠️ 이 함수의 호출자를 늘리는 것이 목표가 아니고 「종결이 맞는가」의 판정 근거를 두는 것이 목표라고 적었음.
