고쳐졌음 (2026-09-19 · TASK-241).

고른 갈래: 결과 화면의 패턴 카드에 진입을 붙이는 쪽(TASK-233 의 제안 ⑴). 근거와 버린 쪽은 TASK-241 노트가 가짐 — 경로 A(세션 안 자연어 요청)는 TASK-7 이 범위 밖으로 갈라 둔 쪽이고 실물 Nova 없이는 관측이 안 됨.

배선 여섯 자리:
- 마이그레이션 031 — learning_sessions 에 nullable focus_pattern_key text 와 빈 문자열을 막는 CHECK. FK 를 걸지 않은 것이 판단임: error_patterns 는 재분석으로 행이 바뀌는 표라 패턴이 사라져도 「그때 이 패턴으로 연습했다」는 사실이 남아야 함. 그래서 id 가 아니라 pattern_key 문자열을 담음. 적용 전 백업 /tmp/omy-backups/ohmyenglish-20260919-1713.sql (pg_dump -n ohmyenglish · 186k).
- services/sessions.load_focus_pattern — pattern_key 로 error_patterns 를 읽어 InstructionFocus 를 만듦. user_id 를 조건에 넣은 것은 남의 패턴으로 드릴이 열리지 않게 하려는 것이고, frequency·next_review_at 을 보지 않는 것은 복습 사다리가 아니라 학습자가 직접 고른 것이라서임.
- _insert_session·create_session·start_shadowing_session 이 focus_pattern_key 를 받음.
- api/ws.py 가 ?pattern= 을 읽어 세션 행에 적음. 없는 키도 오류로 만들지 않음(?item 과 같은 관례) — 다만 세션 행에는 그대로 적음. 「학습자가 그 키로 들어왔다」는 패턴이 실재하는지와 별개이고, 실재하지 않는 키로 들어온 것 자체가 신호임.
- api/ws.py 가 계획의 초점을 고른 패턴으로 «대체»함(model_copy). 덧붙이지 않은 것이 판단임 — focus 는 최대 2개이고 계획의 초점을 남기면 「이것만 연습한다」가 흐려짐. 계획이 없으면 지시문을 지어내지 않고 패턴만 기록함(AS4 규약).
- 프런트: SessionEntry.patternKey · entryQuery·entryFromQuery 양쪽 · dashboardEntryHref 신설 · 결과 화면 카드에 「이 패턴으로 연습하기」. ⛔ entryFromQuery 의 「mode 가 없으면 null」을 넓혔음 — 즉시 드릴은 말하기 세션이고 말하기는 mode 값역에 없어서(없는 것이 기본값) 그 가드가 이 진입을 아예 표현할 수 없었음. 두 이름(mode·pattern)만 명시로 열거해 「세션을 여는 뜻」은 그대로 지킴.

검사: tests/integration/test_ws.py 의 test_ws_pattern_entry_records_the_choice_and_replaces_the_instruction_focus 가 두 자리를 한 검사로 잼(세션 행 기록 + 지시문 초점 대체) + 대조 팔(패턴을 주지 않은 세션의 초점이 계획 그대로). 한 검사로 묶은 것이 의도임 — 기록만 남고 지시문이 안 바뀌면 코치는 다른 것을 연습시키는데 「경로가 있다」로 보임.
