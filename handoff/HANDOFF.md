## 다음 한 걸음

### A절 A-5 — Task 8 남은 절반: 세션 화면 발음 배지

**선행이 끝났다** — 지시문 확정(G-1·G-3)은 `efc6264`로 완료. 이제 배지를 만들 차례다.

백엔드는 이미 `{"type":"pronunciation", …}`을 방송하는데
(`app/audio_gateway/session.py:254-261`) 프론트 `ServerEvent` union과 `page.tsx`의 `switch`에
그 타입이 없다. 고칠 자리 2곳·시각 규약은 `TASKS.md` **A-5**.

✅ **검증 수단 결정 (2026-08-30, 캡틴): 실물 마이크 1회(G-4)에 묶는다.** 스텁 주입 스위치는
테스트 전용 경로를 생산 코드에 심고, 프론트 테스트 프레임워크는 새 의존성이다 — 어느 쪽이든
마이크 1회는 여전히 필요하니 그 한 번에 함께 본다.

**순서**: ~~G-1·G-3~~ → **A-5 배지 구현** → G-4 마이크 1회에서 배지 · 판정 품질 · 픽스처를
한 번에 관측. **Task 8은 그때까지 열어둔다.**

⚠️ 그 프레임은 `target_sound`(기계 키)를 싣는다 — **화면에 렌더하지 않는다**(설계서 §10 미결 4).

**표시 규약 (2026-08-30 캡틴 결정, 이미 결과 카드에 적용됨)**: 기계 키를 화면·응답에 넣지
않고, 시도 1건 = 1카드다(`attempt_seq` 순, 소리별 묶음 없음). 실물 왕복 0회 = 관측된 키
0건이라 표시 사전·`_as_` 분해 규칙은 둘 다 발명값이다. 근거 정본은 설계서 **§10 미결 4**.

⚠️ **지시문이 실제로 Nova 행동을 바꾸는지는 미검증이다** — 자동으로 고정한 것은 "문구가
조립돼 전송 페이로드에 실린다"까지고, 행동 변화도 마이크 1회에서 본다.

📌 **G-5의 기각 근거가 뒤집혔다** — "지시문 주입은 `port.start()` 확장이 필요하다"는 사실이
아니었다. 실제 이음매는 팩토리이고 G-3이 그 통로를 이미 만들었다. 상세는 `TASKS.md` G-5.

`TASKS.md` **G절**. **G-1·G-3은 `efc6264`로 완료.** 착수 순서에 영향을 주는 것만 적으면:

## 발음 서비스 계약 (Task 8이 바로 쓴다)

계획서 본문 서술은 낡았다. 실제 계약은 이것이고 정본은 설계서 §3.1a·§3.2·§4.3이다.

```python
from app.services.pronunciation import (
    link_pattern,         # 시도 1건 → error_patterns. 조건(incorrect+target_sound)은 SQL이 갖는다
    note_transcript,      # 학습자 전사문을 보고 신호가 보이면 기록 (감지기 묶음)
    record_attempt,       # Nova tool 생명주기 — **자기 트랜잭션을 연다**. 패턴 연결까지 한 단위
    record_signal,        # 단발 관측 1건 — outcome에 'pending'·'incorrect'가 없다
    resolve_dangling,     # 종료 수렴 + 패턴 연결 — 이것도 자기 트랜잭션을 연다(savepoint 합성)
)
from app.services.sessions import end_session   # conn을 받는 원시 함수
```

Task 8이 읽을 컬럼: `pronunciation_attempts`의 `target_form`·`spoken_form`·`outcome`·
`signal_source`·`pattern_id`. 패턴의 `frequency`는 **발음 시도 수**다(문법의 occurrence 수와
다른 규약 — `docs/database-schema.md:111`).
**규칙은 서비스가 소유하고 세션은 배선만 한다**(§3.1a) — 새 감지기를 `session.py`에 박지 말고
`note_transcript` 안에 넣는다.
