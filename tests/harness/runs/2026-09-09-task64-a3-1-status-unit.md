# 회차 기록 — A3-1 음성 대조의 판정 단위를 세션에서 status 로 옮김 (TASK-64)

## 1. 무엇이 오탐이었나 — 고치기 전에 직접 재서 얻은 FAIL

교정 2건 세션(`e0c5e580` = `C3f`)을 여섯째로 넣어 돌렸음.

```
세션 6건 · API 상태: analyzing · final · final · partial_failure · connection_failed · no_utterances
--- 판정 (단정 81건 검사) ---
  FAIL  A3-1 음성 대조: 같은 요소의 문구가 상태마다 바뀌지 않았다
        — ['분석 중', '확정', '확정', '부분 실패', '연결 실패', '분석 대상 없음']
판정 FAIL — 어긋난 단정 1건 / 검사 81건
```

앱 결함이 아니고 **대조식의 결함임.** `len(set(texts)) != len(texts)` 는 세션 목록의 중복을 보므로
**「상태당 세션 1건」을 암묵 전제함.** `C3b`·`C3f` 가 둘 다 `final` 이라 라벨이 **정당하게** 겹침.

이 오탐이 `browser_leg.md` §11-9 가 요구한 「교정 2건 이상 세션 추가」를 막고 있었고, 그래서 A4-2
기대값 교차 대조가 매 회차 미확인으로 남았음.

## 2. 무엇으로 바꿨나

판정을 `check_status_label_variation` 으로 빼고 **status 단위**로 재게 함. 두 단정으로 갈랐음.

| | 단정 |
|---|---|
| ① | 같은 status 는 같은 문구를 냄 — 갈리면 화면이 status 의 함수가 아님 |
| ② | 서로 다른 status 는 서로 다른 문구를 냄 — 겹치면 상수를 렌더하고 있음 |

⛔ **항진명제 방어는 그대로 계승했음** — status 가 2종 미만이면 평가하지 않고 미확인으로 냄.
바뀐 것은 세는 대상이 세션에서 status 로 옮겨간 것뿐임.

⛔ **함수를 코루틴 밖으로 뺀 이유가 판별력임.** `main_async` 안에 있으면 무력화 입력으로 잴 수
없음. 지금은 `test_c3_gates.py` 가 브라우저 없이 다섯 갈래를 잼 — 실물 회차 통과 · 같은 상태 셋을
오탐하지 않음 · 서로 다른 상태가 같은 문구를 내면 FAIL · 같은 상태가 두 문구를 내면 FAIL ·
1종이면 미확인이고 검사 수 0.
