## 2. AC#2 — 왜 틀이 나오는가: **같은 이름의 필드가 계약이 둘이다**

`services/analysis.py` 의 `_TARGET_FORM_RULES` 가 `target_form` 을 **일반형으로 요구한다** — 그 문구가
자리표시자를 **좋은 예로** 들고 문장을 **나쁜 예로** 든다:

```
문장이 아니라 패턴을 적는다. 자리표시자(`+ 장소 명사`, `+ 동사 과거형`)나 규칙 조각을 써서 …
좋은 예 / 나쁜 예(그 문장의 교정문을 그대로 넣은 것):
- `go to the + 장소 명사` / `I usually go to the gym after work.`
```

⇒ **모델은 지시를 그대로 지켰다.** `I finished the + 업무 산출물 명사 (report / presentation / draft)`
는 문법 경로에서 **옳은 값**이다(교정 카드의 연습 목표).

⛔ **어긋난 것은 라우팅이다.** `pronunciation_attempts.target_form` 의 계약은
「Nova 가 시범한 **문장**」이고(`services/pronunciation.py` 의 그 컬럼 주석 · 화면 라벨이 「시범 문장」),
`TASK-88` 의 설계가 finding 의 `target_form`(일반형)을 그 자리에 넣었다. **이름이 같고 계약이 다르다.**

⚠️ finding 은 **문장을 이미 갖고 있다** — `correction`(교정문)과 `original_span`(학습자가 말한 조각).
즉 고칠 재료가 있다.

## 3. AC#3 은 판단이다 — 후보와 대가

| 후보 | 무엇 | 대가 |
|---|---|---|
| ① 라우팅만 고침 | 발음 기록의 `target_form` ← finding 의 **`correction`**, `spoken_form` ← `original_span` | 화면은 여전히 「관찰된 신호」 갈래라 **내 발화·판정을 안 그린다** — 값은 옳아지고 표시는 그대로다 |
| ② 화면 갈래만 가름 | `transcript_analysis` 를 별도 라벨로 3줄 카드로 그린다 | 값이 틀 그대로라 「시범 문장」 자리에 한국어 자리표시자가 보인다 |

⛔ **내가 고르지 않는다** — 학습자에게 보이는 문구가 바뀌는 것이 AC#3 의 조건이다.

## 5. AC#4 — 구현과 단정

**라우팅**(TDD · 실패를 먼저 봤음):
⚠️ **기존 테스트가 이 축을 가르지 못했다** — 픽스처의 `target_form` 과 `correction` 이 둘 다

`spoken_form` 에 남는 것)을 같은 테스트가 함께 단정함.

**타입**: `tsc` 가 계약 구멍을 잡았음 — 프론트의 `signal_source` 값역에 `transcript_analysis` 가
**빠져 있었다**(024 이후 낡았음). 값역을 채웠고 그 경위를 타입 주석에 적었음.

**화면 실측**(`shot-after-fix.png` · 네 카드를 한 화면에 둠):

```
카드 ①  시범 문장 / I think it's three. / 내 발화 / I sink it's sree. / 다시 연습해요
카드 ②  교정문 / I finished the + 업무 산출물 명사 (…) / 내 발화 / the la porte … / 다시 연습해요
카드 ③  관찰된 신호 / (전사문이 한국어로 인식되었습니다)
카드 ④  교정문 / the report / 내 발화 / the la porte … / 다시 연습해요
```

⚠️ **②는 고치기 «전»에 쌓인 행이고 ④는 고친 뒤 새로 들어올 행이다** — 픽스처에 둘을 함께 둬서
**같은 화면에서 대조**했음. ⇒ 화면 고침은 옛 행에도 적용되고(내 발화·판정이 보인다) 라우팅 고침은
새 행의 첫 줄을 문장으로 만든다. **스크린샷을 직접 열어 봤음.**
⛔ 옛 행을 **소급해 고치지 않았다** — 저장된 값을 뒤늦게 바꾸면 그때 무엇이 실렸는지가 사라진다.
