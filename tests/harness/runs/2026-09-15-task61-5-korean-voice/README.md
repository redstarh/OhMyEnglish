## 4. 다음 관측 후보 — 후보 ②를 가르는 가장 싼 것

**한국어 «비명령» 발화 한 팔**: 표지 없는 한국어 학습 발화를 흘려 코치가 말하는지 본다.
- 말하면 → 침묵은 **명령 경로**에 걸린 것(tool 호출과 함께 발화가 죽는 것)
- 말하지 않으면 → 침묵은 **한국어 입력 자체**에 걸린 것이고 음성 명령 축의 문제가 아니다

⛔ 이 회차의 상한을 다 썼으므로 돌리지 않았음. 픽스처는 새로 만들어야 함(한국어 학습 문장).

## 4-1. 후보 ②를 가른 팔 — 한국어 학습 발화에는 코치가 말했음

§4 의 처방을 그대로 돌렸음. 상한을 **Nova 2세션**(본 1 + 예비 1)으로 대화에서 먼저 적었고 **1세션만**
썼음. 픽스처를 새로 만들었음 — `vc08_ko_learning.wav`(`say -v Yuna "저는 어제 회의에서 보고를
했어요."` · 2.30초 · 16kHz 모노).

| 무엇 | 값 (세션 `0b36951e`) |
|---|---|
| `recv.audio` | **150** — 코치가 말했음 |
| 코치 발화 | *"Great job! You said you reported at a meeting yesterday. … Try saying: "I gave a report at the meeting yesterday." Can you say that sentence for me?"* |
| 발화 행 | `learning` 2행(학습자 1 · 코치 1) · `voice_command` 0 |
| 보조 신호 | `pronunciation_attempts` 에 `korean_transcript` 1행 — 한국어 전사를 감지하는 기존 경로가 정상 작동했음 |
| `voice_command` 프레임 | 0 — 표지가 없으므로 tool 이 오지 않았음(정상) |

⇒ **후보 ②(「Nova 가 한국어 입력 턴에서 발화를 만들지 않는다」)가 반증됐음.** 한국어 입력 자체는
침묵을 만들지 않음.

**남는 것은 좁혀진 하나뿐임 — 「한국어 «명령» 턴에서만 발화가 죽는다」.** 영어 명령 턴에서는 발화와
tool 이 함께 왔고(4/4 · `task61-4` §2) 한국어 명령 턴에서는 tool 만 왔음(0/4). 즉 조합(한국어 + tool
호출)이 조건임. ⚠️ 원인을 여기서 더 좁히지 않음 — 프롬프트로는 안 된다는 것이 §1 에서 이미 반증됐고,
앱은 음성을 합성하지 않으므로 **남은 수단은 결정 104 가 기각한 「화면 문구」뿐**임. 그 판단을 사용자에게
올림(§6).

## 6. 사용자에게 올릴 것 하나

**좁혀진 사실**: 한국어 명령 턴에서만 코치의 발화가 죽는다(0/4). 한국어 학습 발화는 말하고(§4-1),
영어 명령 턴은 발화와 tool 이 함께 온다(4/4).

프롬프트로 고치는 길은 §1 이 반증했고 앱은 음성을 합성하지 않으므로 남은 수단은 하나다 —
**결정 104 가 기각한 「앱이 화면 문구로 확인을 보여 준다」를 한국어 경로에 한정해 살리는 것.**
⛔ 그것은 결정 102 ③(음성으로 한 번 더 확인)을 한국어에서만 화면 확인으로 바꾸는 일이므로 사용자
판단이 필요하다. 대안은 **그대로 두는 것**이고, 그때 한국어 음성 종료는 학습자가 안내를 듣지 못한 채
확인을 말해야 하므로 사실상 쓰기 어렵다.
