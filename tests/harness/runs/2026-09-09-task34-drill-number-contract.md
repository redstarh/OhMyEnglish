# 회차 기록 — 결과 화면의 「수를 그리지 않는다」 계약을 게이트로 만듦 (TASK-34)

캡틴 결정 10·18 이 걸린 계약인데 **사람의 주의에만 의존**하고 있었음. `directPCount` 는 측정만
하고 단정하지 않아 새 `<p>` 한 줄을 모름.

## 1. AC3 판단 — 어디에 두는가와 그 근거

**결론: `c3_results_screen.py` 에 순수 함수(`check_drill_contract`)로 두고 `test_c3_gates.py` 가
무력화로 지킴. 별도 프론트 테스트를 만들지 않았음.**

| 후보 | 판정 | 근거 |
|---|---|---|
| 별도 프론트 테스트 | ⛔ 하지 않음 | **이 리포에 JS 테스트 러너가 없음** — `app/frontend/package.json` 의 스크립트는 `dev`·`build`·`start`·`lint` 넷이고 devDependencies 에 jest·vitest·jsdom 이 0건임(직접 읽어 확인). 러너와 jsdom 을 새로 들이는 것은 이 단정 하나가 요구하는 비용을 넘음 |
| `directPCount` 를 등호로 올림 | ⛔ 하지 않음 | 그 수는 계약이 아니라 **구현의 부산물**임. 정당한 `<p>` 하나만 늘어도 깨짐 — `TASK-55` 가 출구 링크를 넣을 때 **실제로 늘었음**. 계약이 말하는 것은 개수가 아니라 무엇이 그려지는가임 |
| C3 하네스에 순수 함수 + pytest 게이트 | ✅ 채택 | 계약은 **렌더된 출력**에 걸리고 그것을 관측하는 것은 브라우저 다리뿐임. 판정을 순수 함수로 빼면 픽스처로 **브라우저 없이** 회귀를 잡음 — `TASK-64` 가 같은 이유로 A3-1 을 뺐고 그 형태를 따랐음 |

⚠️ 하네스는 `browser_leg.md` 의 소유물이라 함부로 고치지 않음 — 그래서 그 문서에 `A3-3` 을
정식으로 등록했고 §5 표에 두 갈래와 무력화 결과를 적었음.

## 2. 무엇을 재는가 — 「그 두 수가 없다」로 재지 않은 이유

⛔ `exchanges_observed=2` 를 문자열 `"2"` 로 찾으면 **양쪽으로 틀림**: 교정문에 우연히 든 `2` 가
오탐이 되고, 화면이 `9 / 12` 대신 `아홉` 이나 `2회` 로 새면 못 잡음.

재는 것은 **「API 가 준 학습자 문구에 없던 숫자가 화면에 있는가」** 임. 화면이 소유하는 상수에는
숫자가 하나도 없음(직접 확인: 상태 라벨 5개 · 부분 실패 안내 · 미달 안내 · 발음 라벨 셋 · 빈 상태
문구 · 출구 문구). 그래서 이 형태가 드릴 두 수뿐 아니라 `occurrences` 같은 **다른 숫자 누출까지**
막음.

⛔ **`target_form` 을 허용 목록에 넣지 않았음.** 응답에는 있지만 교정 카드가 렌더하는 것은
`original_span`·`correction`·`reason` 셋임. 렌더되지 않는 필드를 허용하면 그 필드에만 있는 숫자가
화면에 새도 통과함.

⛔ **`bodyText` 가 아니라 `main` 만 읽음.** `next dev` 가 body 에 주입하는 스크립트에 숫자가 섞여
있어 `bodyText` 로 재면 항상 FAIL 임. 학습자가 보는 것은 `main` 안이고 계약이 걸린 범위도 그것임.
⚠️ 자르지 않음 — 잘린 뒤쪽에 숫자가 있으면 못 봄.

## 3. 판별력 — 실물에서 FAIL 을 관측했음 (AC1)

임시로 `<p>{drill.exchanges_observed} / {drill.exchanges_expected}</p>` 를 결과 화면에 넣고 회차를
돌렸음.

```
--- 판정 (단정 94건 검사) ---
  FAIL  [final_two] 화면에 API 가 주지 않은 숫자가 있다 — ['2', '20']
        · drill={'exchanges_observed': 2, 'exchanges_expected': 20}. 결과 화면은 수를 그리지 않는다(결정 10·18)
판정 FAIL — 어긋난 단정 1건 / 검사 94건
```

되돌린 뒤 같은 회차가 **94건 전건 통과**임. 되돌림은 두 가지로 확인했음 —
`grep TASK34_MUTATION_TEMP` 0건 · `git diff --stat` 이 그 파일에 아무것도 내지 않음.

⚠️ **표본이 `final_two` 하나임** — `drill` 키를 가진 세션이 그것뿐임(나머지 다섯은 키가 없음).
그 세션이 `2 / 20` 이라 **미달 갈래만** 실물로 평가됨. 「달성 세션에는 아무것도 그리지 않는다」는
회차에서 **미확인**으로 내고 통과로 세지 않음 — 그 갈래의 판별력은 아래 무력화가 지킴.

## 4. 게이트가 잡는 갈래 — `test_c3_gates.py`

| 무력화 입력 | 기대 |
|---|---|
| 두 수를 화면에 렌더 | FAIL — 새어 나온 수를 `['2', '20']` 으로 이름 붙여 냄 |
| `occurrences` 같은 다른 숫자(`2회`) 누출 | FAIL |
| **API 가 준 교정문에 든 숫자**(`2026년`) | **통과 — 오탐하지 않음**(음성 대조) |
| 미달인데 안내 문장이 없음 | FAIL |
| **달성인데 안내 문장이 있음** (AC2 갈래) | FAIL |
| `drill` 키가 없는데 안내 문장이 있음 | FAIL |

세 번째 줄이 없으면 이 단정은 「숫자가 하나도 없다」와 구별되지 않아 교정문에 연도가 든 세션에서
잡음 생성기가 됨.
