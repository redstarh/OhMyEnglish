# 회차 — `TASK-26.6`: 주간 리포트 화면을 브라우저로 확인한다

세션 `ohmyenglish-f4` · 2026-09-14 KST · 브랜치 `design/first-vertical-slice`
회차 디렉터리: `tests/harness/runs/2026-09-14-task26-weekly/`

> **왜 브라우저가 필요한가**: 단위·통합은 API 가 값을 내주는 것까지만 잰다. 「화면이 그 값을 어떻게
> 그리는가」와 **점수를 그리지 않는가**는 화면 쪽 사실이고, 프런트 테스트 인프라가 0이라 이 회차가
> 그 축의 유일한 증거다.

---

## 0. 스택 — 공유 자원을 건드리지 않았다

| 무엇 | 값 |
|---|---|
| DB | 검증 전용 `ohmy_weekcheck`(`createdb` + `migrate.py` 전체 · 마이그레이션 **21건**) |
| 백엔드 | `:8013` · `WORKER_ENABLED=false` · 어댑터 기본값 `stub` |
| 프런트 | 리포의 `app/frontend` 를 `next dev --port 3000` · `NEXT_PUBLIC_API_BASE=http://127.0.0.1:8013` |
| 자료 | 지난 주(`2026-09-07`) 리포트 **1행**을 손으로 심었다 — 사실 셋 + 상위 오류 둘 + 판단 둘 |

⚠️ **모델을 부르지 않았다** — `insights` 를 손으로 심었다. 이 회차가 재는 것은 **화면**이고 모델
출력의 품질은 §4 에 미결로 남긴다.

## 1. 확인한 것 넷 — 직접 돌려 얻은 출력

**⑴ API 가 실물 경로에서 사실과 판단을 함께 낸다**:

```
{"week_start":"2026-09-07","analyzed":true,
 "metrics":{"top_patterns":[{"category":"article","occurrences":4,…}],"pattern_count":2,
            "session_count":4,"occurrence_count":6},
 "insights":{"improving":["관사를 붙인 문장이 지난 주보다 늘었어요."],
             "next_scenarios":["업무 상태 보고에서 과거 시제를 연습해요."]}}
```

**⑵ 화면이 그것을 그린다** (`weekly-report.png` — 직접 열어 봤다):
주 범위가 **`9월 7일 ~ 9월 13일`**(월요일~일요일)이고, 「학습 4회 · 오류 6건 · 패턴 2종」 한 줄,
「이 주에 자주 틀린 것」 둘, 「나아진 것」 하나, 「다음 주에 해 볼 것」 하나.
⛔ **점수·등급·달성률이 화면에 0건이다** — PRD §15.3 의 비범위와 R13-5 의 톤 계약이다.

**⑶ 「아직 없음」이 빈 표를 그리지 않는다** (`weekly-not-yet.md` · 행을 지운 뒤):

```
# 주간 학습 리포트
아직 만들어진 주간 리포트가 없어요. 한 주 학습이 쌓이면 만들어져요.
← 학습 히스토리로
```

API 는 그때 `{"week_start":null,"analyzed":false,"metrics":{},"insights":{}}` 로 **200** 을 준다
(`api-empty.json`) — 404 가 아니다.

**⑷ 닿는 길이 있다** (`history-links.md`): 히스토리 화면의 링크가
`주간 리포트 보기 → /history/weekly` 다. ⛔ 화면이 있어도 길이 없으면 소비자가 0곳인 것과 같다.

## 2. 정리와 무변경 확인 — 직접 돌려 얻은 값

| 무엇 | 확인 |
|---|---|
| 프런트·백엔드 | 종료 — `:3000`·`:8013` 이 **`000`**(연결 불가) |
| 검증 전용 DB | `dropdb ohmy_weekcheck` **exit 0** |
| **공유 dev DB** | `schema_migrations` **20** · 최대 **`022`** · `learning_sessions` **17** · `to_regclass('weekly_reports')` **null** |

⛔ **`weekly_reports` 가 dev DB 에 «없다»는 것이 023 미적용의 증거다** — 그 적용은 `TASK-26.7`
(승인 사안)의 몫이다. ⚠️ 처음 무오염 조회가 그 표를 세려다 `relation … does not exist` 로 실패했고,
그 실패 자체가 답이었다 — 조회를 `to_regclass` 로 바꿔 사실로 적었다.

## 3. 이 회차가 잡은 것

없다. 화면·API·링크가 처음부터 의도대로 났다.
⚠️ 앞선 회차(`TASK-66.7`)가 상대 경로 결함을 잡았으므로 이번에는 `lib/api.ts` 의 `API_BASE` 를
처음부터 썼다 — 같은 실패를 반복하지 않았다.

## 4. 이 회차가 닫지 못한 것

- ⛔ **모델 출력의 품질.** `insights` 를 손으로 심었으므로 「모델이 쓸 만한 판단을 내는가」는
  실물 호출 회차가 필요하고, 그것은 dev DB 적용(`TASK-26.7`) 뒤에 사람이 읽어야 한다.
- **여러 주가 쌓인 화면**을 보지 못했다 — 한 행만 심었다. 「가장 최근 주가 이긴다」는 API 단정이
  이미 재고 있다(`test_the_latest_week_wins`).
- **좁은 화면(모바일)의 배치**를 보지 못했다.
