# 테스트↔수정 왕복 원장

**상한: 10차수.** 10차수에 닿으면 오류가 남아 있어도 중단하고 캡틴에게 보고한다
(캡틴 지시 2026-08-26). 무한 루프 방지가 목적이며, 수렴하면 그 전에 닫는다.

루프 구조:

```
테스트(이 세션 claude_air_5-49:0.0) ──오류 전달──▶ 수정(claude_air_3-14:0.0)
              ▲                                              │
              └────────────── 완료 보고(tmux send-keys) ──────┘
```

역할 분리 원칙: **테스트 세션은 앱 코드를 수정하지 않고, 수정 세션은 자기 수정을 스스로
합격 판정하지 않는다.**

### 4차수 범위 확장 — 캡틴 지시 (2026-08-26)

원래 4차수는 "미실행 Nova 시나리오 + 회귀"였다. 캡틴이 4건을 추가했다.

1. **발음 교정 루틴이 있는지 테스트하고, 없으면 수정** → **P계층 신설**
   (`../scenarios-P-pronunciation.md`)
2. **오류가 이후 학습 패턴에 Agent가 반영되는지 동작 검증 시나리오 추가** → **M계층 신설**
   (`../scenarios-E-agent-learning.md` M계층)
3. **정확한 음성과 약간 잘못된 발음이 있는 음성을 함께 준비** → 픽스처 6개 생성 완료
   (`p1a/p1m/p1k` · `p2a/p2m/p2k` — 같은 문장을 발음만 바꾼 쌍)
4. **테스트 내용과 결과를 계속 기록해 향후 통합테스트에 반영** → 이 원장 + `run-N.md` +
   계층별 시나리오 정본으로 유지

#### 개시 전 확보한 실측 (P계층 설계의 전제)

`spike_nova_protocol.py`로 Nova 직접 왕복 3건. **약한 발음 오류는 ASR이 원문으로 복원해
전사문에 흔적이 0**이고(`p1m` 전사문이 `p1a`와 동일), **강한 억양은 한글로 전사된다**
(`p1k` → `아이싱크 아이파운드 …`). agent는 두 경우 모두 발음을 지적하지 않았다.
→ 발음 교정은 **문법 교정만 있고 발음 특화는 없다**가 실측으로 확정. 상세·한계는 P계층 문서 §2.

#### 4차수 결과에 따른 분기 (수정 왕복 개설 조건)

| 조건 | 처리 |
|---|---|
| P5에서 한글 전사문이 job을 `failed`로 수렴시키거나, P6에서 오탐 패턴이 생긴다 | **결함** → 4차수 수정 왕복 개설(O-1 묶음) |
| P3에서 발음 교정이 없음이 확인된다 | 프롬프트 수준 교정 추가는 **기능 신설** → 캡틴 승인 후 전달 |

#### 4차수 실측 결과 (2026-08-26 실행 완료)

**분기: 신규 결함 0건 → 수정 왕복 열지 않음.** 루프 4/10 사용, 일시 종료.

- **P5가 clean이었다** — 한글 전사문에 대해 job이 `done`·attempts 1·findings 0으로 수렴했다
  (120초 관측). 최우선 위험이 결함이 아니었다.
- **발음 교정 부재 확정** — `p1m`의 전사문이 `p1a`와 문자 단위로 동일하고 agent 응답도 동일했다.
  개입 가능 지점은 `nova.py:77` `SYSTEM_PROMPT` 한 곳뿐이다(캡틴 결정 대기).
- **학습 반영 부재 확정** — 패턴 8개를 쌓은 뒤에도 agent 응답이 3차수 N5와 글자까지
  같았다. 통제된 대조로 활용 링크 부재를 고정했다.
- 캡틴 결정으로 **P·M만** 돌렸다. N6~N13 · B1~B4 · 회귀 · P8 · **P계층 `p2` 쌍**은 **5차수 몫**
  이며, 3차수의 "B1~B4 대체 커버" 판단은 **아직 검증되지 않았다**.

#### 4차수의 절차 교훈 (독립 critic 패스에서 드러났다 — 통합테스트에 반영할 것)

1. **M계층 판정의 산출물이 남지 않았다.** agent 전사문을 근거로 삼았는데 git 추적본·로컬
   로그·DB 어디에도 없다(세션은 teardown cascade로 삭제). **판정 근거로 쓸 전사문은 반드시
   `runs/<차수>/`에 덤프한다** — `.harness/`는 `.git/info/exclude`(로컬 전용)라 증거가 못 된다.
2. **완료 선언은 시나리오 단정의 픽스처 범위까지 적는다.** P1~P7을 "완료"라 썼지만 단정은
   `p1`+`p2` 두 쌍이고 실제로는 `p1`만 돌렸다 — 요약표가 이를 가렸다.
3. **판정 기준이 캡틴 미승인이면 판정에 그 사실을 붙인다** (P3이 그랬다).
4. **절대값 단정 금지는 시나리오 정본에도 적용된다** — M1이 `frequency` 2를 절대값으로 단정해
   함정 H-4를 정본 자체가 위반하고 있었다. 델타로 고쳤다.
5. **"두 화면이 같다"를 스크린샷으로 증명할 수 없다.** P7의 두 장이 **바이트 동일**(MD5
   `8c58621b…`)이었고 화면에 세션 식별 픽셀이 0이라, 같은 캡처를 두 이름으로 저장한 것과
   구별되지 않는다. → **대조용 캡처는 세션 id·전사문이 프레임에 들어가게 찍고, 제출 전
   `md5`로 서로 다른 파일인지 확인한다.**
6. **차수 간 대조에 수치를 쓰려면 그 차수의 상태를 그때 기록해야 한다.** M0-②가 "3차수는
   패턴 1개"라 썼는데 3차수는 Q1(E6 주입)을 N5보다 먼저 돌려 최소 2개였다. 좌변을 재지 않고
   기억으로 적어 틀렸다.
7. **cwd가 게이트의 일부다.** ruff 설정은 `app/backend/pyproject.toml`뿐이라 리포루트에서
   돌리면 기본 규칙으로 56 errors가 난다. "리포루트도 clean"이라 적혀 있던 것은 오류였다.

#### 4차수 결과에 대한 캡틴 결정 (2026-08-26)

**발음 교정: 수정하지 않고 기록만 한다.** "없으면 수정" 지시의 대상이었지만, 4차수 결과가
"고장난 것이 아니라 없는 기능"임을 보였다(P5 clean) — 게다가 문법 교정은 이미 작동한다(O-3).
상위 순서는 복습(L계층)과 학습 코치 Agent다. 재개 조건과 층 선택은
`../scenarios-P-pronunciation.md` §5에 남겼다.

**M계층도 같다** — 부재를 기준선으로 고정했고 구현은 3단계 학습 코치 Agent의 몫이다.

### 3차수를 연 근거

2차수 종료 시점에는 F-2가 캡틴 결정을 기다려 루프를 멈췄다. 캡틴이 결정을 내렸다(2026-08-26):

- **F-2 → 선택지 B**(패턴 수준 일반형). 근거: 문장별 교정형은 이미
  `error_occurrences.correction`에 있어 중복이다. `target_form`이 따로 존재할 값이 있으려면
  "이 패턴을 연습할 때 익힐 형태"여야 한다.
- **사용자 부분 전사문 UI → 선택지 ①**(`userSpeechStart`~`userSpeechEnd` 구간에 "듣고 있어요").
  근거: Nova는 사용자 부분 전사문을 주지 않는다(N-1 실측 — ASR은 `FINAL` 한 블록).
- **순서 → Nova 먼저.** 복습(L계층)은 오류가 쌓여야 의미가 있고, 실음성이 붙어야 쌓인다.

그리고 N-0·N-1이 완료돼 **프로토콜이 실증**됐으므로 어댑터 구현이 가능해졌다
(`scenarios-N-real-voice.md`).

## 차수별 회귀 중점 규칙

새 차수를 시작할 때 **전건 재실행이 목적이 아니다.** 아래 두 묶음을 먼저 돌린다.

1. **이전 차수에서 실패했거나 결함이 나온 케이스** — 수정이 실제로 들었는지.
2. **아직 수행하지 않았던 케이스** — 커버리지를 넓힌다.

그다음 회귀 확인용으로 핵심 계약(A1 프레임·B계층 5상태·D계층 게이트)을 돌린다.

## 전달·보고 규약

- 전달: `tmux send-keys -t claude_air_3-14:0.0 '<한 줄>' Enter` — 줄바꿈은 조기 전송된다.
- 보고: 수정 세션이 `tmux send-keys -t claude_air_5-49:0.0 '<한 줄>' Enter`로 이 세션에 알린다.
- 전달 내용은 **파일 경로로 지목**한다(본문 붙여넣기 금지) — 무엇을 읽고 고쳤는지 추적된다.

## 수정 세션에게 — 보고 대상이 무엇인지

`claude_air_5-49:0.0`은 셸이 아니다. **tmux 페인 주소**이고 그 안에서 이 하네스를 운영하는
**또 다른 Claude Code 세션**(테스트 세션)이 대화형으로 돌고 있다. 그래서:

- `tmux send-keys`로 보낸 텍스트는 **그 세션의 사용자 프롬프트가 된다.** 셸 명령이 아니다.
- `Enter`를 **별도 인자로** 붙여야 실제로 전송된다. 빼면 타이핑만 되고 멈춘다.
- 텍스트는 **한 줄로** 보낸다 — 줄바꿈에서 조기 전송된다.
- 테스트 세션이 하는 일: 보고를 받으면 `README.md`의 절차로 **살아 있는 스택을 상대로 회귀
  테스트를 돌리고**(위 "2차수 회귀 계획") 결과를 이 원장에 기록한다. 수정이 들었는지는
  **테스트 세션이 판정한다** — 수정 세션이 자기 수정을 합격 처리하지 않는다.

### 수정 작업의 환경 제약 (반드시 지킬 것)

1. **워크트리를 새로 만들지 않는다.** 테스트 스택이 `/Users/redstar/MyProject/OhMyEnglish`를
   직접 서빙한다 — 프론트 dev 서버(`:3000`)와 백엔드(`:8002`)가 그 경로에서 떠 있다. 다른
   워크트리에서 고치면 **테스트가 수정 전 코드를 검증한다.** 부득이 워크트리를 썼다면 보고
   전에 `design/first-vertical-slice`로 병합하고 그 사실을 보고에 적는다.
2. **백엔드는 재기동하지 않아도 된다** — 프론트엔드만 고치는 경우. 백엔드 파이썬 소스를
   고쳤으면 `--reload`가 없으므로 **반영되지 않는다**: 보고에 "백엔드 소스 변경 있음"을
   명시하면 테스트 세션이 재기동한다. 직접 재기동한다면 baseline 명령을 그대로 쓴다 —
   `cd app/backend && WORKER_ENABLED=false VOICE_ADAPTER=stub .venv/bin/uvicorn app.api.main:app --port 8002 --log-level warning`.
   ⛔ **`WORKER_ENABLED=false` 를 빼지 마라 — 기본값이 `True` 다**(함정 `H-AS`). 이 줄은
   2026-09-09 까지 그 플래그가 **없는** 형태였고, 그대로 따르면 워커가 켜져 보존 세션이 파괴된다.
3. **`.env`를 편집하지 않는다.** 자격증명이 들어 있고 플래그는 환경변수로만 넘긴다.
4. **DB를 건드리지 않는다.** `harness_*` 테이블과 보존된 E계층 세션은 다음 차수의 재현
   데이터다(위 "1차수 미정리 상태" 참조).
5. `tests/harness/**`와 `docs/design/**`은 수정 금지. `docs/ops/2026-08-26-test-harness*.html`도
   테스트 세션 소유다.
