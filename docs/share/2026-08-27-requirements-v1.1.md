## 1. 제품 한 줄

사용자의 음성 영어 발화를 분석하고, **반복 오류를 패턴 단위로 저장해 다음 학습에 반영**하는 개인화 Speaking Agent. 일상 대화에서 시작해 IT 프로젝트 리딩·보고 영어까지 확장한다.

## 2. 해결할 문제

1. 대화 중 교정은 받지만, **다음 학습에서 같은 오류가 다시 연습되지 않는다.**
2. 문법 학습과 실제 말하기가 분리되어 있다.
3. 업무 상황에서 즉시 쓸 수 있는 표현을 체계적으로 연습하기 어렵다.

## 3. 성공 지표

| 목표 | 지표 |
|---|---|
| 매일 말하기 습관 | 주 4회 이상, 세션당 10분 이상 |
| 반복 오류 감소 | 상위 3개 패턴의 4주 재발률 30% 이상 감소 |
| 업무 보고 자신감 | 4주차에 60초 상태 보고 완주 |
| 개인화 적합성 | 복습 추천 적합 4/5 이상 |

## 4. 기능 요구사항 (v1.0 확정분)

### 4.1 Speaking Coach

- CEFR **A2 안팎**에서 시작하고 성공률에 따라 난이도를 조절한다.
- **사용자 발화 비중 65% 이상**을 목표로 한다.
- 한 번에 질문 하나만. 막히면 선택지·힌트를 준다.
- 교정 순서: `원문 → 더 자연스러운 문장 → 한 줄 이유 → 2회 변형 발화`
- 한 턴에 교정은 **최대 1~2개**. 모든 오류를 지적하지 않는다.
- 일일 권장량은 **한도가 아니라 권장**이다. 채운 뒤에도 추가 학습이 가능하다.

### 4.2 일상 대화·Q&A 드릴

- 주제: 인사, 하루 일과, 식사, 취미, 약속, 감정, 길 묻기, 작은 부탁, 의견 말하기
- 매 드릴은 `질문 듣기 → 답변 → 짧은 후속 질문 → 다른 표현으로 다시 답하기` **4턴 이상**
- 같은 목표 문형을 **3~5개의 다른 질문**에서 사용하게 한다.
- 일상 문맥 → 업무 문맥으로 전이한다. (`I need to buy groceries.` → `I need to finish the test report.`)
- 사용자가 "이 패턴으로 연습 만들어줘"라고 요청해 즉시 드릴을 만들 수 있다.

### 4.3 오류 기억과 복습

- 오류 분류 7종: **시제 · 관사 · 전치사 · 어순 · 동사 형태 · 업무 표현 · 발음/억양**
- 틀린 문장이 아니라 **재사용 가능한 패턴**으로 저장한다.
- 복습 우선순위는 빈도·최근성·영향도·자가 난이도를 **사실로 제공하고 판단은 Agent가** 한다.
- 같은 패턴을 **최소 3개의 다른 상황**에서 재사용한다.
- 복습 주기 **1일 · 3일 · 7일**

### 4.4 추가 학습

- 대시보드에 권장량 완료 여부와 무관하게 **항상** 진입점을 제공한다.
- 선택지: `자유 대화` · `약점 패턴 집중` · `질문 답변 5개` · `업무 역할극` · `쉐도잉` · **`발음 집중`(v1.1 신설)**
- 피로를 감지하면 종료를 제안할 수 있지만 **요청을 막지 않는다.**

### 4.5 음성 제어

- UI 버튼과 **동일한 행동**을 음성으로 수행할 수 있다.
- 명령: 시작/계속/추가 학습, 모드 변경, 반복, 천천히, 힌트, 다음, 일시정지, 종료, 복습·리포트 보기
- 한국어와 간단한 영어 모두 지원한다.
- 학습 답변과 명령을 혼동하지 않게 **명령 버튼** 또는 **"Oh My English"** 호출어를 쓴다.
- 종료·삭제 같은 큰 명령은 **한 번 더 확인**한다.

### 4.6 업무 영어

- 시나리오: daily update, blocker 공유, 일정 변경, 우선순위 조율, incident update, stakeholder 보고
- 보고 구조: `Current status → What changed → Risks/blockers → Decision needed → Next steps`

### 4.7 쉐도잉

- 30~90초 짧은 오디오·영상을 **문장 단위**로 제공한다.
- 순서: 듣기 → 따라 말하기 → 녹음 비교 → 본인 상황으로 바꿔 말하기
- 외부 영상은 **메타데이터·링크만** 보관하고 사용자가 고른 것만 과제로 쓴다.

### 4.8 비기능

- 오류 기록과 녹음을 사용자가 **열람·수정·삭제**할 수 있다.
- Agent 응답은 음성 대화에서 **짧고 즉시성** 있게 유지한다.
- **교정 근거·난이도 선택·추천 이유를 화면에서 확인**할 수 있어야 한다.
- 실시간 음성은 Nova Sonic, 오류 분석·장기 계획은 Claude로 **분리**한다.
- **음성 응답 경로에서 장기 분석을 동기 호출하지 않는다.**
- 음성 녹음은 **기본 미저장(opt-in)**.

## §10 발음 시범·재발화

### 왜 필요한가 — 실측된 공백

4차수가 앱 경로로 확인한 것:

| 실측 사실 | 뜻 |
|---|---|
| 학습자가 목표음을 치환해 발음해도 ASR이 **원문으로 복원**한다 | 전사문에 발음 오류의 흔적이 **0** |
| 그래서 전사문만 받는 분석 경로는 발음을 판정할 수 없다 | **원리적 한계**다. 구현 실수가 아니다 |
| 오디오를 직접 듣는 실시간 음성 모델도 발음을 지적하지 않았다 | **지시문에 발음 규칙이 없었다** |
| 강한 억양은 전사문을 한국어로 뒤집는다 | 학습 가치가 0인 세션이 된다 |

결과적으로 **학습자는 "잘못 말했는데 아무 피드백이 없는" 세션을 받는다.**

> 📌 **2026-08-27 추가 실측**: 지시문에 발음 규칙을 넣자 Nova가 **실제로 교정했다** —
> *"Say this after me: I think I found three very useful videos."* → *"Now you repeat that sentence for me."*
> 즉 **능력 부재가 아니라 지시 부재**였다.

### 요구사항

| # | 내용 |
|---|---|
| **R10-1** | 발음이 불명확하거나 목표음에서 벗어났다고 판단되면 Agent는 **올바른 발음으로 그 문장을 다시 읽어준다.** 틀린 소리를 함께 짚는다 |
| **R10-2** | 시범 뒤 따라 말할 기회를 준다. 재발화 결과를 `성공 / 실패 / 판정불가`로 **기록한다** |
| **R10-3** | 발음 판정 주체는 **오디오를 직접 듣는 실시간 음성 모델**이다. 전사문 기반 분석은 발음을 판정하지 않는다 |
| **R10-4** | 판정 보조 신호 2개를 관측·기록한다 — ① 전사문에 한국어가 섞인 경우 ② Agent가 되물은 경우 |
| **R10-5** | 일반 세션에서 발음 개입은 문법 교정과 **예산을 다투지 않는다** — 보조 신호가 뜬 경우만 즉시 개입. 발음 집중은 **추가 학습의 독립 항목** |
| **R10-6** | 발음 오류도 **재사용 가능한 패턴**으로 저장해 이후 학습에 재등장한다 |
| **R10-7** | **오디오 원본은 저장하지 않는다.** 남는 것은 판정 결과와 시범 문장이다 |
| **R10-8** | 발음 개입이 있어도 "한 턴 1~2개 교정"과 "사용자 발화 65%"를 깨지 않는다 |

### 범위 경계 — 채점이 아니라 시범이다

| 하는 것 | 하지 않는 것 |
|---|---|
| 올바른 발음으로 문장 재현 | 음소 단위 점수 |
| 재발화 성공·실패 기록 | 발음 CEFR 등급 |
| 발음 약점을 다음 세션 초점으로 재등장 | 원어민 유사도 지표 |
| 보조 신호 기록 | 오디오를 분석 경로로 보내는 채점 파이프라인 |

### 수용 기준

- **AC10-1** 목표음을 치환해 발화했을 때 → **문장 전체**를 올바른 발음으로 다시 읽어주고 따라 말하기를 요청한다
- **AC10-2** 재발화가 끝났을 때 → 결과가 기록되어 **다음 세션 계획이 읽을 수 있다**
- **AC10-3** 강한 억양으로 전사문이 한국어가 되었을 때 → 보조 신호로 기록되고 **분석 파이프라인은 실패하지 않는다**
- **AC10-4** 한 턴에 문법·발음 오류가 함께 있을 때 → 개입이 1~2건을 넘지 않는다
- **AC10-5** 추가 학습에서 발음 집중을 선택했을 때 → 발음 시범·재발화가 주 활동이 된다

### 스토리보드 (7스텝)

```
S1  학습자 발화        "I sink I pound sree bery useful bideos."
S2  전사문 확정         → 화면에는 "i think i found three very useful videos."로 적힌다
                          (글자로는 오류가 안 보인다 — 그래서 음성을 듣는 모델이 판정한다)
S3  발음 배지 표시     🔊 발음 교정 중
S4  시범              "Say this after me: I think I found three very useful videos."
                        시범 문장을 큰 글씨로 강조 + 0.75× / 1.0× / 다시 듣기
S5  따라 말하기 요청   "Now you repeat that sentence for me."   🎙 마이크 활성
S6  재발화            내 발화를 시범 문장 바로 아래 나란히 표시
S7  결과 배지         ✓ 좋아요 / 다시 연습할 거예요 / 잘 안 들렸어요
                        → 실패면 다음 세션 초점 패턴으로 재등장
```

**결과 화면 변화**: 4차수에서 정확 발음 세션과 오류 발음 세션의 결과 화면이 **똑같이 "표시할 교정이 없습니다."** 였다. v1.1부터 문법 교정 카드 아래에 **발음 카드**가 붙고, 발음 시도가 있으면 빈 상태 문구를 쓰지 않는다.

## §11 학습 이력 기반 추천 학습 루틴

### 왜 필요한가 — 저장은 되고 활용은 안 된다

4차수 M계층 실측:

- 오류 패턴이 **8개 쌓인 뒤에도** 세션 시나리오가 **고정 첫 행 하나**였다.
- Agent 응답이 패턴이 훨씬 적던 이전 세션과 **동일**했다.
- **복습 과제 0행**, **다음 복습일 전부 비어 있음** — 1·3·7일 주기를 갱신하는 주체가 없다.

즉 **오류는 기억되지만 쓰이지 않는다.** §2의 첫 번째 문제가 그대로 남아 있다.

### 요구사항

| # | 내용 |
|---|---|
| **R11-1** | 오류 이력을 영속 저장한다 — 패턴, 발생 위치와 교정, **교정 후 재발화의 정답 여부**, 발음 시도 |
| **R11-2** | 세션마다 "오늘 무엇을 어떻게 연습할지"를 이력에서 정한다 — 초점 패턴 **1~2개**, 질문 **3~5개**, 난이도, 추천 이유 |
| **R11-3** | **추천 이유는 필수**다. 왜 이 연습인지 화면에서 확인할 수 있어야 한다 |
| **R11-4** | 계획 생성은 **학습자가 기다리는 경로에 두지 않는다** — 앞선 세션이 끝날 때 미리 만든다 |
| **R11-5** | 계획이 없거나 실패해도 **학습은 시작된다** |
| **R11-6** | 복습 1·3·7일을 실제로 갱신한다. **다시 틀린 패턴은 주기를 되돌린다**(재발을 7일 뒤로 미루면 복습이 무의미하다) |
| **R11-7** | 난이도는 **한 번에 한 단계씩만** 이동하고 **하향도 허용**한다 |
| **R11-8** | 만성 약점 판정의 **임계값을 제품이 발명하지 않는다** — 조회는 사실(재발 세션 수·재발 일수·지속 기간·휴면 후 재발)을 주고 판단은 Agent가 한다 |
| **R11-9** | **발음 시도 이력도** 계획 입력에 포함되고, 발음도 초점 패턴이 될 수 있다 |
| **R11-10** | Agent의 **관찰 기록**을 보존한다(예: "짧은 문장에서는 관사를 붙이는데 길어지면 빼먹는다"). 덧붙이기만 하고 지우지 않아 되돌릴 수 있다 |

### 수용 기준

- **AC11-1** 복습일이 지난 패턴이 여럿일 때 → **그 전부가** 계획 입력에 포함된다. 하나라도 누락되면 실패
- **AC11-2** 재발이 가장 심한 패턴 → 초점 패턴에 포함되고 질문 3~5개가 그 패턴을 유발하며 **추천 이유가 비어 있지 않다**
- **AC11-3** 계획 생성이 실패했을 때 → 폴백으로 정상 시작된다
- **AC11-4** 잘못된 계획(이유 없음 / 질문 수 위반 / 난이도 두 단계 도약) → **저장을 거부한다**
- **AC11-5** 같은 패턴을 두 세션 연속 틀렸을 때 → 두 번째 세션의 대화가 첫 세션과 **구별된다**
- **AC11-6** 발음 재발화에 반복 실패한 패턴 → 다음 계획의 초점 패턴에 포함될 수 있다

### 스토리보드

```
세션 종료
  └─ 같은 트랜잭션에서 계획 생성 작업 등록
       └─ 오류 이력 · 재발화 결과 · 발음 시도를 읽어
          초점 패턴 1~2개 / 질문 3~5개 / 난이도 / 추천 이유

다음 세션 시작
  └─ 준비된 계획을 읽기만 한다   (대기 0)
       └─ 없으면 기본 시나리오 폴백   (학습이 막히지 않는다)
```

**화면 예시 — "왜 이걸 연습하나요?"**

> **오늘의 초점 2개**
> ① `article_missing_before_noun` — 5번 틀렸고 3일 만에 또 나왔어요
> ② `pronunciation_th_as_s` — 따라 말하기가 2번 실패했어요
>
> **추천 이유**
> 문장이 길어질 때만 관사를 빼먹고 있어요. 오늘은 **긴 업무 문장**에서 같은 형태를 5번 말해볼게요.

요구사항 문서지만 오해를 막기 위해 적는다 — **아래는 요구사항이 아니라 현황이다.**

| 요구사항 | 상태 |
|---|---|
| §4 v1.0 확정분 | Phase 1 첫 수직 슬라이스 완료. 음성 명령·업무 역할극·쉐도잉·주간 리포트는 이후 단계 |
| **§10 발음 시범·재발화** | 🔨 설계 확정, 구현 진행 중 (기록 계층까지) |
