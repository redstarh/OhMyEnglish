1. 무엇이 막혔는가 — 실측

앱이 Nova 2 Sonic 을 부르면 Bedrock 이 다음 문구로 거부함(2026-11-01 응답 본문).

User: arn:aws:iam::<ACCOUNT_ID>:user/ohmyenglish-local is not authorized to perform:
bedrock:InvokeModel on resource: arn:aws:bedrock:us-east-1::foundation-model/amazon.nova-2-sonic-v1:0
because no identity-based policy allows the bedrock:InvokeModel action
확인한 것값
사용자의 인라인 정책BedrockNovaAndClaudeInvoke 하나가 그대로 있음
그 정책이 허용하는 리전us-west-2 뿐임(Nova 모델 ARN · Claude 추론 프로필 ARN)
앱이 지금 쓰는 리전us-east-1 — 2026-10-18 TASK-281.1 에서 바뀜
마지막 Nova 성공2026-09-26 (dev DB llm_calls)

정책은 사라지지 않았음. 앱의 리전만 바뀌어 정책의 허용 대상에서 벗어났음. 그래서 고칠 것은 정책의 Resource 리전 하나임.

Bedrock API 키(AWS_BEARER_TOKEN_BEDROCK)로는 대신할 수 없음. 양방향 음성 스트림은 API 키를 This operation does not support API Keys 로 거부함(2026-08-25 · 2026-11-01 두 번 실측).

2. 붙일 정책 JSON

리전 자리를 * 로 둠. 앱 리전이 다시 바뀌어도 이 정책이 막지 않게 하려는 것임. 모델과 동작은 이전과 같고, 넓어지는 것은 리전뿐임.

{
  "Version": "2012-10-17",
  "Statement": [
    {
      "Sid": "NovaSonicBidirectional",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithBidirectionalStream"
      ],
      "Resource": "arn:aws:bedrock:*::foundation-model/amazon.nova-2-sonic-v1:0"
    },
    {
      "Sid": "ClaudeAnalysis",
      "Effect": "Allow",
      "Action": [
        "bedrock:InvokeModel",
        "bedrock:InvokeModelWithResponseStream"
      ],
      "Resource": [
        "arn:aws:bedrock:*:*:inference-profile/us.anthropic.claude-opus-5",
        "arn:aws:bedrock:*::foundation-model/anthropic.claude-opus-5*"
      ]
    }
  ]
}

3. 방법 A — AWS 콘솔에서 고치기

  1. 관리자 권한으로 AWS 콘솔에 로그인함(SSO 포털의 AdministratorAccess 역할).
  2. IAM → Users → ohmyenglish-local 를 엶.
  3. Permissions 탭의 정책 목록에서 BedrockNovaAndClaudeInvoke 를 누름.
  4. Edit 을 누르고 편집기를 JSON 으로 바꿈.
  5. 기존 내용을 모두 지우고 위 2절의 JSON 을 붙여 넣음.
  6. Next → Save changes 를 누름. 반영까지 수십 초가 걸릴 수 있음.

콘솔에 새 사용자를 만들거나 액세스 키를 새로 발급할 필요는 없음. 지금 키(2026-08-25 발급, Active)를 그대로 씀.

4. 방법 B — 터미널에서 고치기 (SSO 관리자 세션)

SSO 세션이 살아 있으면 터미널에서 한 번에 바꿀 수 있음. 위 JSON 을 policy.json 으로 저장한 뒤 실행함.

aws sso login --profile kjihoon-bedrock        # 세션이 없을 때만
aws iam put-user-policy --profile kjihoon-bedrock \
  --user-name ohmyenglish-local \
  --policy-name BedrockNovaAndClaudeInvoke \
  --policy-document file://policy.json

바뀐 내용은 다음 명령으로 다시 읽어 볼 수 있음.

aws iam get-user-policy --profile kjihoon-bedrock \
  --user-name ohmyenglish-local --policy-name BedrockNovaAndClaudeInvoke \
  --query 'PolicyDocument.Statement[].Resource'

5. 고쳐졌는지 확인하기

리포의 스파이크 스크립트가 IAM 사용자 키(app/backend/.env)로 Nova 스트림을 한 번 열어 봄. 이 스크립트는 DB 를 쓰지 않음. SSO 임시 키가 환경에 남아 있으면 그쪽이 먼저 쓰이므로 아래처럼 지우고 돌림.

cd ~/MyProject/OhMyEnglish/app/backend
env -u AWS_BEARER_TOKEN_BEDROCK -u AWS_PROFILE \
    -u AWS_ACCESS_KEY_ID -u AWS_SECRET_ACCESS_KEY -u AWS_SESSION_TOKEN \
    .venv/bin/python ../../scripts/spike_nova_bidirectional.py

마지막 줄이 PASS: 요청이 수락되고 스트림이 10초간 유지됐다 이면 고쳐진 것임.

여전히 FAIL: AccessDeniedException 이면 OMY_SPIKE_CAPTURE_BODY=1 을 앞에 붙여 다시 돌림. 그러면 거부된 정확한 ARN 이 보이고, 그 ARN 을 정책의 Resource 에 더하면 됨.

6. 고친 뒤 달라지는 것

  • 백엔드는 .env 의 IAM 사용자 키로 Nova 를 부를 수 있게 됨. SSO 로그인 없이 상시로 띄울 수 있음.
  • 실행 아이콘(TASK-291)은 지금 SSO 세션을 쓰도록 만들어져 있음. SSO 가 없으면 로그인 창을 띄움. IAM 경로로 바꾸고 싶으면 따로 요청하면 됨.
  • 되돌리려면 2026-11-01 이전 정책으로 바꿈. 그 정책은 위 JSON 에서 * 리전 세 자리를 us-west-2 로 바꾸고, 추론 프로필의 계정 자리를 실제 계정 ID 로 바꾼 것과 같음.
