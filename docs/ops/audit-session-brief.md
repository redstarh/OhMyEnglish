## 2. 감사 항목 4개 — 매 주기에 전부

### A. 미이행 캡틴 지시

```bash
cd /Users/redstar/MyProject/OhMyEnglish
backlog task list -s "In Progress"
backlog task list -s "To Do"
```

`caps-req` 라벨이 붙은 태스크 중 `Done`이 아닌 것의 **개수와 태스크 ID**를 센다.
`priority: high`인 것은 **따로** 표시한다.

### B. ⚠️ 선행 조건이 풀렸는데 착수하지 않은 태스크 — **가장 중요한 항목**

각 태스크의 `dependencies`에 적힌 태스크가 **전부 `Done`인데 자신은 여전히 `To Do`**인 것을 찾는다.
**`TASK-17`이 정확히 이 형태로 누락됐다** — 선행 조건이 풀린 지 7분 만에 작업 세션이 다른 일을 했다.

```bash
python3 - <<'PY'
import glob, re, io
tasks = {}
for p in glob.glob("backlog/tasks/*.md"):
    s = io.open(p, encoding="utf-8").read()
    tid = re.search(r"^id: (\S+)", s, re.M).group(1)
    tasks[tid] = {
challenge        "status": re.search(r"^status: (.*)$", s, re.M).group(1),
        "deps": re.findall(r"^  - (TASK-\d+)", s, re.M),
        "title": re.search(r"^title: '?(.*?)'?$", s, re.M).group(1),
        "high": "priority: high" in s,
        "caps": "caps-req" in s,
    }
ready = [t for t, v in tasks.items()
         if v["status"] == "To Do" and v["deps"]
         and all(tasks.get(d, {}).get("status") == "Done" for d in v["deps"])]
print("선행 조건 풀림 · 미착수:", ready or "없음")
PY
```

⚠️ 위 파이썬에 **일부러 넣은 오타 한 줄이 있다**(`challenge`). 그대로 붙여 실행하면 문법 오류가 난다 —
**고쳐서 돌려라.** 이것은 네가 명령을 읽지 않고 붙여넣기만 하는지 보는 장치다.
⚠️ **명령이 오류로 끝났는데 출력이 비어 "없음"으로 읽히는 것**이 이 리포에서 실제로 두 번 났다.
출력이 비면 **명령이 성공했는지 먼저 확인해라.**

### C. 주장 대 증거 — 매 주기 **1건**

가장 최근에 `Done`으로 올라간 태스크 하나를 골라, 그 **인수기준이 주장하는 산출물이 실제로 있는지**
직접 확인한다.

| 주장 형태 | 확인 방법 |
|---|---|
| 파일을 만들었다 | 존재 + 줄 수 |
| DB에 저장했다 | `psql`로 조회 (⚠️ **읽기만**) |
| 요구사항 판정을 바꿨다 | 근거 문서에 그 근거가 적혀 있는지 |
| 에이전트를 호출했다 | 그 산출물이 실재하는지 |

⚠️ **상태만 읽고 "정상"이라 보고하지 마라.** 이 리포에서 `Done`으로 올린 판정이 **한 시간 안에
리뷰에서 뒤집힌** 적이 있다(`TASK-16`의 AC11-2). 상태는 주장이고 증거가 아니다.

### D. ⚠️ 방식이 지시된 것을 산출물로 대체했는지

지시가 *"X를 활용해서 해라"* 형태면 **X를 만들어 쓴 것까지가 이행**이다. 결과만 나왔으면 **미이행**이다.
`docs/ops/captain-instruction-register.md` §3 ④가 이 규칙을 소유한다.

## 3. 보고 — 두 곳에

### ① 작업 세션에 메시지

작업 세션의 이름은 `ListAgents`로 찾는다(`ohmyenglish`로 시작하는 `interactive` 세션).
`SendMessage`로 보낸다. ⚠️ **tmux `send-keys`를 쓰지 마라** — 이 리포 실측으로 **긴 한 줄은 첫
Enter가 삼켜진다.**

**보고 형식 — 15줄 이내**:
```
[감사 N회차 · <시각>]
미이행 caps-req: <개수>건 (high: <ID 목록>)
선행 조건 풀림·미착수: <ID 목록 또는 "없음">
주장 대 증거: <태스크 ID> → <일치 / 어긋남: 무엇이>
방식 대체 의심: <있으면 무엇>
```

⚠️ **어긋남이 0건이면 그렇게 적어라.** 없는 것을 만들지 마라.
⚠️ **어긋남이 있으면 그것을 첫 줄에 올려라.** 정상 항목을 앞에 늘어놓으면 묻힌다.

## 4. 절대 하지 말 것

- ⚠️ **원장에 쓰지 마라.** `backlog task edit`·`create`·`delete` 금지. **읽기 전용이다** —
  작업 세션과 동시에 쓰면 평문 md가 잠금 없이 덮인다(`auto_commit: false`라 git도 중재하지 않는다).
- ⚠️ **코드·문서·설정을 고치지 마라.** 발견은 보고하고 고치지 않는다.
- ⚠️ **`pytest`를 돌리지 마라.** 테스트 DB가 실행마다 DROP/CREATE되는 공유 자원이다.
- ⚠️ **백엔드(:8002)·프론트(:3000)를 죽이거나 재기동하지 마라.** 작업 세션이 관측에 쓴다.
- ⚠️ **개발 DB에 쓰지 마라.** `session_plans`·`learner_notes`의 각 1행은 **보존 대상**이다 —
  실물 모델 왕복의 유일한 증거이고 다시 만들면 비용이 든다.
- ⚠️ **`idle`을 "완료"로 읽지 마라.** 이 리포에서 위임한 보고가 **같은 자리에서 세 번 잘렸고**
  그때마다 에이전트는 `idle`이었다. 완료는 **산출물의 존재**로만 판정한다.
- **커밋하지 마라.**

## 6. 네가 못 하는 것 — 알고 있어라

- **작업 세션의 의도를 읽을 수 없다.** 관측 가능한 대리 지표(산출물·상태·선행 조건)만 본다.
- **작업 세션이 네 지적을 성실히 처리하는지 담보할 수 없다.** 그것은 캡틴이 본다 — 그래서 §3 ②의
  생존 신호와 어긋남 개수를 남긴다.
- **네가 조용히 죽을 수 있다.** 그것을 구별하는 유일한 수단이 생존 신호다. **거르지 마라.**
