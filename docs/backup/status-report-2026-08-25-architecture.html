03-A · QUEUE SEMANTICS

비동기 분석 — PostgreSQL 큐와 멱등성

이 앱에서 세션 분석은 유일한 산출물이다. 프로세스가 죽으면 학습 데이터가 통째로 사라지므로 BackgroundTasks만 쓰는 단순안을 버리고 테이블 기반 큐(analysis_jobs)를 만들었다.

claim과 lease

규칙결정이유
claim 방식짧은 트랜잭션에서 FOR UPDATE SKIP LOCKED → 트랜잭션 닫고 Claude 호출 → 별도 트랜잭션에서 완료 처리 Claude 호출을 트랜잭션 안에 두면 커넥션을 수십 초 잡는다
lease tokenclaim 1회당 고유 token을 locked_by에 기록 (워커 ID가 아니다) 같은 워커가 재claim해도 token이 달라져 이전 시도의 늦은 쓰기를 구분한다
원자화 조건결과 쓰기·done·재큐·failed 전부 where status='running' and locked_by=:token lease를 잃은 워커가 결과 쓰기나 재큐를 먼저 해 새 claim 상태를 오염시키는 것을 막는다. 0행이면 그 시도를 통째로 버린다
attemptsclaim 시점에 +1 — 상한 5 = “최대 5회 호출” lease 만료 회수도 재claim이므로 attempt를 소비한다
종료 조건attempts >= 5면 terminal failed + last_error 상한이 없으면 영구 재시도한다 (poison-pill)
reaperclaim에 내장 — lease 만료 + 상한 도달 좀비를 failed로 수렴 구현 중 발견한 계획 결함(좀비가 영구 루프) 해소
백오프available_at = clock_timestamp() + attempts × 1분 Postgres now()는 트랜잭션 고정이라 백오프가 무력화된다 — 실측으로 확인
lease 기간5분 (설계 발명값)Claude 호출 상한 대비 여유값. 조정 시 AC 수치도 갱신

멱등성 — 재시도가 안전해야 한다

가장 까다로운 실패는 “결과 저장은 끝났지만 status 갱신 전 크래시”다. 같은 작업이 재실행되므로 재실행이 중복을 만들지 않아야 한다.

  • 발화 단위 replace — 한 트랜잭션에서 delete from error_occurrences where utterance_id = :id 후 새 결과 집합을 insert. 재시도하면 같은 집합으로 교체될 뿐이고, 재분석 결과가 달라져도 최신 결과만 남는다
  • unique(utterance_id, pattern_id) 초안은 철회 — 한 문장에 관사 누락이 두 곳 나오는 정상 데이터를 잃는다. replace는 복수 occurrence를 보존하면서 멱등하다
  • frequency는 실제 행 수에서 재계산 — 무조건 +1이면 재시도마다 부풀어 오른다
  • last_seen_at은 utterances.created_at(발화 시각) 기준 — occurrence 시각을 쓰면 replace가 재삽입할 때마다 현재로 당겨진다
  • 확정 전사문 저장과 analyze_utterance 등록은 한 트랜잭션 — 분리하면 그 사이 크래시에서 분석되지 않는 발화가 영구히 남는다
  • (job_type, utterance_id) partial unique가 pending/running 동안 중복 등록을 차단
  • unique(session_id, sequence_no)는 중복 제거 장치가 아니라 Gateway 이중 commit 버그를 막는 무결성 가드

pattern_key 정규화 계약 — 앱의 핵심 약속

“같은 오류는 하나의 패턴으로 병합”은 Claude가 세션을 넘어 같은 오류에 같은 key를 내놓는다는 전제 위에 있다. 자유 생성에 맡기면 missing_article_before_place와 article_missing_before_gym이 병합되지 않아 약속이 조용히 무너진다.

1. 재사용 우선

프롬프트에 해당 사용자의 기존 pattern_key 목록(카테고리·target_form 포함)을 주입하고, 같은 유형이면 기존 key를 그대로 쓰게 한다.

2. 신규만 생성

기존에 없을 때만 {category}_{영문_스네이크} 형식으로 만든다 (예: article_missing_before_noun).

3. 표기 정규화

공백·대소문자 변형은 기존 표기로 정규화한다.

실물 증명: 가짜 클라이언트로는 이 계약이 동어반복이 되므로 W-live 스모크가 실제 Claude로 판정한다. 2발화 연속 분석에서 article_missing_before_noun이 발화 2에서 재사용되어 error_patterns 1행 · error_occurrences 2행 · frequency=2로 병합됐다.

Claude 출력은 신뢰할 수 없는 외부 데이터

필수 필드 누락 · severity 미정의값 · confidence 범위(0~1) 초과 · 카테고리 CHECK 밖 값은 저장 전 스키마 검증에서 거부되고 job이 last_error와 함께 실패한다. 반면 오류 0건 결과는 정상 done이다 — 빈 전사문도 findings 0건 done으로 처리해 재시도를 소진하지 않는다.
