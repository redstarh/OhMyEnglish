# 음성 인식·발화 및 음성 제어 설계

> 이 문서는 초기에 작성한 일반 음성 설계다. 현재 채택된 구체 아키텍처는 [Nova Sonic + Claude 목표 아키텍처](nova-sonic-claude-architecture.md)를 우선한다.

## 결론

MVP는 **브라우저 WebSocket 기반 Nova 2 Sonic 실시간 음성 대화 + Python 서버의 Claude Opus 5 학습 분석 경로**로 구현한다.

- 실시간 대화: 사용자가 말하면 Agent가 자연스럽게 듣고 응답하며, 사용자가 끼어들면 즉시 멈춘다.
- 학습 기록: 전사문, 교정, 오류 패턴, 복습 과제를 서버에 구조화해 저장한다.
- 음성 제어: UI 버튼과 동일한 명령을 Intent(의도)로 분류해 안전한 함수 호출로 실행한다.

이 설계는 자연스러운 회화와 재현 가능한 학습 분석을 분리한다. 브라우저 오디오는 Python/FastAPI Audio Gateway를 거쳐 Bedrock Nova 2 Sonic 양방향 스트림으로 전달한다. 장기 학습 분석에는 전사문과 세션 이벤트를 저장하고 Claude Opus 5 Worker가 별도로 처리한다.

## 아키텍처

```text
[Browser]
  Mic + Speaker + UI
       │ Secure WebSocket
       ▼
[Nova Sonic Bidirectional Stream]
  turn detection / interruption / spoken reply
       │ transcript + tool calls
       ▼
[Application Server]
  session state ─ command router ─ learning planner
       │                    │
       ▼                    ▼
[PostgreSQL]           [Object Storage]
 patterns, reviews      optional audio recordings
```

## 음성 인식(STT)

### 학습 대화

1. 사용자가 UI의 **말하기** 버튼을 누르거나 활성 세션에서 발화한다.
2. 브라우저는 마이크 권한을 요청하고 오디오 프레임을 Secure WebSocket으로 Audio Gateway에 보낸다.
3. 세션의 발화 감지(VAD)가 사용자 말의 시작·끝을 감지한다.
4. UI에는 부분 전사문을 회색으로, 확정 전사문을 일반 텍스트로 표시한다.
5. 확정 전사문과 타임스탬프를 `utterances`에 저장한다.
6. 턴 종료 또는 세션 종료 시, 오류 분석 Agent가 전사문을 패턴·교정·복습 과제로 변환한다.

**권장 정책:** 실시간 화면의 전사문은 대화 반응성을 위해 사용하고, 학습 기록은 세션 종료 후 다시 검증·정규화한다. 사용자는 전사문을 직접 고칠 수 있어야 한다. IT 고유명사(API, AWS, 서비스명)는 개인 사전에 등록해 오류 분석 시 보존한다.

### 음성 명령

음성 명령은 별도 마이크를 만들지 않고 같은 입력 스트림을 사용한다.

- 기본: 화면의 `음성 명령` 버튼을 누른 뒤 말한다. 가장 오인식이 적은 MVP 방식이다.
- 활성 학습 중: “**Oh My English,** …”으로 시작하면 명령으로 처리한다.
- 명확한 단일 명령은 호출어 없이도 처리한다. 예: “Repeat that slowly.”
- 항상 듣는 wake word는 MVP에 넣지 않는다. 개인정보·배터리·오인식 이슈가 있어, 사용자가 명시적으로 활성화한 후에만 후속 버전에서 제공한다.

## 음성 발화(TTS)

### 대화 응답

- 실시간 세션의 음성 응답을 그대로 재생한다.
- 발화 속도는 기본 보통으로 시작하고, 사용자가 “천천히 말해줘”라고 말하면 해당 세션의 응답 길이·속도를 낮춘다.
- Agent 발화는 1~2문장 중심으로 제한한다. 긴 설명은 화면의 전사문·예시 영역으로 보낸다.
- 사용자가 말하기 시작하면 재생을 중단한다(barge-in). 이것은 회화에서 매우 중요하다.

### 쉐도잉

- 문장 단위 재생, 0.75x/1.0x 속도, 반복 재생, 전사문 숨기기를 제공한다.
- 사용자의 발화 뒤에는 즉시 짧은 피드백을 하고, 정확도 분석은 세션 종료 후 종합한다.

## 명령 Router

실시간 Agent는 명령을 임의의 텍스트 행동으로 처리하지 않고, 아래처럼 제한된 도구 호출로 바꾼다.

| 발화 | Intent | 실행 |
|---|---|---|
| “추가 연습 시작” | `start_extra_practice` | 추가 학습 선택 패널 열기 |
| “질문 다섯 개 더” | `start_qa_drill` | 현재 문형의 새 질문 5개 생성 |
| “이 문법으로 연습 만들어줘” | `practice_current_pattern` | 선택 오류 기반 드릴 생성 |
| “천천히 다시 말해줘” | `repeat_slowly` | 마지막 Agent 문장을 느리게 재생 |
| “힌트 줘” | `show_hint` | 문장 시작어/선택지 표시 |
| “다음 문제” | `next_item` | 현재 항목을 건너뛰고 기록 |
| “일시정지” | `pause_session` | 오디오·타이머 일시정지 |
| “오늘 학습 끝낼게” | `request_end_session` | 종료 확인 UI/음성 질문 |

명령 처리 결과는 화면 토스트와 짧은 음성 확인으로 동시에 알려준다.

## 구현 순서

1. **Phase 1:** Push-to-talk, 전사문 표시, 음성 응답, 수동 UI 제어.
2. **Phase 2:** Nova Sonic 양방향 실시간 세션, 자동 턴 감지, 끼어들기, 음성 명령 8종.
3. **Phase 3:** 세션 종료 후 오류 패턴 추출, 1·3·7일 복습 자동 생성.
4. **Phase 4:** 쉐도잉 속도 제어, 사용자 사전, 선택형 wake phrase.

## 보안·개인정보

- API 키는 브라우저에 직접 넣지 않는다. 서버가 세션별 임시 자격 증명을 발급한다.
- 음성 녹음 저장은 opt-in으로 두며, 기본은 전사문과 학습 결과만 보관한다.
- 녹음·전사문·오류 패턴은 사용자가 개별 삭제·내보내기할 수 있어야 한다.
- 음성 제어가 끝내기·삭제를 요청하면 반드시 확인 단계를 거친다.
