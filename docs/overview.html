1. 지금 되는 것 — 기능 요약

아래는 코드에 실재하는 기능만 적은 것임. 판정 근거는 각 행이 가리키는 문서와 작업 원장임.

기능무엇을 함어디서 소유
음성 대화 세션 WebSocket /ws/session 한 개가 세션 하나를 이룸. 부분·확정 전사문, 상대 발화 오디오, 끼어들기, 발화 시작 감지를 이벤트로 흘림. 음성 어댑터는 실연동(Nova Sonic)과 스텁 재생 둘임. nova-sonic-claude-architecture.md
학습 모드 다섯 speaking · shadowing · review · pronunciation · scenario_intake. 값역은 DB CHECK 가 가둠. PRD §7 · database-schema.md
오류 패턴 학습 발화 묶음마다 실물 모델이 교정을 내고, 같은 오류는 pattern_key 하나로 병합됨. 발생 건마다 원문·교정·이유·심각도·확신도를 남김. first-vertical-slice-design.md
복습 사다리 패턴별로 1·3·7일 주기 과제를 만들고, 다음 세션의 재시도 판정(정답·오답·판정불가)으로 단계를 옮김. review-task-history-design.md
다음 세션 계획 세션이 끝나면 다음 세션의 초점·질문·목표 수준을 만들어 두고, 다음 진입이 그것을 읽어 지시문을 조립함. learning-coach-agent-design.md
세션 총평 전사문에서 잘한 점과 약점을 뽑아 세션 행에 저장하고 결과 화면이 그것을 읽음. session-summary-design.md
일일 오류 요약 그날의 오류를 종별로 집계해 하루 한 행으로 저장함. 날짜 경계는 users.timezone 임. daily-error-summary-design.md
일일 완료 판정 · 연속 학습일 그날 마친 시나리오 수로 완료를 판정하고, 연속 학습일과 히스토리를 화면에 냄. daily-completion-design.md · streak-and-history-design.md
주간 리포트 지난 주의 세션 수·발생 수·상위 패턴을 사실로 모으고, 모델이 그 위에 총평을 붙임. 한 주에 학습이 0건이면 그 주 리포트는 생기지 않음(세션 종료가 유일한 주기 신호임). weekly-report-design.md
쉐도잉 클립을 듣고 따라 말한 녹음을 저장하고, 낭독 전사문을 붙임. 만료 녹음은 워커가 걷음. shadowing-task-design.md · shadowing-clip-audio-design.md
발음 시범·재발화 발음 전용 모드가 시범을 주고 재발화를 기록함. 점수·등급은 내지 않음(범위 밖). pronunciation-echo-design.md · pronunciation-mode-design.md
무대(시나리오) 시드 무대 30행 + 학습자 대화 5문답에서 만든 전용 무대. 진입은 새 무대와 반복을 70/30으로 섞음. scenario-generator-design.md · scenario-rotation-70-30-design.md
영상으로 배우기 YouTube 영상을 등록하고 구절을 뽑아 학습 자원으로 씀. 화면 둘과 API 여섯임. video-learning-design.md
낱말 뜻 조회 POST /api/vocab/lookup — 화면에서 낱말을 눌러 뜻을 물음. 워커를 끈 서버에서도 동작함. video-learning-design.md
음성 명령 진입 말로 학습을 시작·전환함. 세션 행에 started_via='voice_command' 가 남아 버튼 진입과 구별됨. additional-learning-entry-design.md
비용 기록 모델 호출마다 목적·모델·토큰을 llm_calls 에 남김. 계획 job 만 다른 모델을 씀. ops/local-run.md

3. 뒷단 — 세션·큐·분석

경로 하나를 끝까지 따라가면 이러함.

단계무엇이 일어남
1. 진입화면이 /ws/session 을 열고 세션 행이 생김. 모드·진입 출처·진입 수단이 그 행에 남음.
2. 대화음성 어댑터가 부분·확정 전사문과 상대 발화 오디오를 흘림. 확정 발화만 저장됨.
3. 턴 경계학습자 발화 묶음이 닫히면 analyze_utterance job 이 걸림.
4. 세션 종료한 트랜잭션에서 종료를 적고 job 을 더 걺 — 총평 · 다음 계획 · (intake 면) 무대 생성 · (지난 주 리포트가 없으면) 주간 리포트.
5. 워커동시성 1의 단일 루프가 job 을 하나씩 집어 처리함. 임대(lease)로 이중 처리를 막고, 큐가 비면 회복 셋을 돌림 — 고아 세션 닫기 · 잃은 묶음 걷기 · 만료 녹음 스윕.
6. 저장발화 단위로 지우고 다시 넣는 방식이라 재실행이 중복을 만들지 않음. 패턴 빈도는 더하지 않고 발생 행에서 다시 셈.
7. 조회결과 화면이 job 상태로 화면 상태를 정함 — 진행 중이면 교정을 계산하지도 않음.

재시도 규약이 사유에 따라 갈림(2026-09-20 정제). 모델 출력이 계약을 어긴 경우는 다른 표본이 지킬 수 있으므로 최대 5회 재시도함. 반면 입력이 바뀔 수 없는 실패는 첫 시도에 종결함 — 전사문이 빈 경우와, 모델이 지시대로 「무대가 없다」고 답한 경우임. 근거는 scenario-generator-design.md §5 의 정제 절이 소유함.

4. 데이터와 시각 규약

DB 는 PostgreSQL 17 이고 스키마는 ohmyenglish 임. 마이그레이션 29개(최신 031)로 세움. 제품 표 17개와 하네스 기준선 표 4개, 그리고 마이그레이션 기록 표 하나가 있음.

묶음표
학습자·세션users · learning_sessions · utterances · session_plans · learner_notes
오류·복습error_patterns · error_occurrences · review_tasks · pattern_attempts · daily_error_summary · weekly_reports
학습 자원learning_scenarios · shadowing_items · youtube_videos
발음pronunciation_attempts
큐·비용analysis_jobs · llm_calls

시각 규약 셋을 지킴. 사건 시각은 전부 timestamptz 이고 DB 와 서버 기본 시간대는 UTC 임. 「오늘·어제」 같은 달력 날짜는 current_date 로 만들지 않고 users.timezone 으로 접어서 구함 — UTC 자정부터 09시(KST)까지 그 두 값이 하루 어긋남. 저장된 값을 변환해 갱신하지 않고 읽을 때만 변환함.

이 인스턴스는 다른 서비스와 공유함. 인스턴스 단위 조작을 하지 않고 DB 단위로만 다룸 — ops/shared-database-guide.md.

5. 실행 방법

상세와 함정의 정본은 ops/local-run.md 임. 여기에는 순서만 둠.

# 0) DB — homebrew postgresql@17 (:5432) 하나. 보통 부팅 시 떠 있음
scripts/dev_db.sh status

# 1) 마이그레이션 + 시드 (멱등)
app/backend/.venv/bin/python scripts/migrate.py

# 2) 백엔드 — 포트 8002 · --reload 없음(소스를 고쳤으면 재기동)
cd app/backend && .venv/bin/uvicorn app.api.main:app --port 8002

# 3) 프런트 — 포트 3000
cd app/frontend && npm run dev

포트를 틀리면 조용히 실패함. 이 머신의 :8000 은 다른 서비스가 씀 — 백엔드는 반드시 --port 8002 로 띄우고, 프런트의 .env.local 이 :8002 를 가리켜야 함. 브라우저 확인은 localhost:3000 으로 함 (127.0.0.1 로 열면 개발 서버가 자원을 막아 화면이 붙지 않음).

리스너 확인은 lsof -nP -iTCP:8002 -sTCP:LISTEN -t 로 함. lsof -ti:8002 는 클라이언트까지 잡아 오독됨.

6. 검증 — 게이트와 회차 도구

게이트 일곱을 돌려 판정함. 2026-09-20 실측값을 괄호에 적음.

cd app/backend && ./.venv/bin/pytest -q                      # 1428 passed
cd app/backend && ./.venv/bin/ruff check . ../../tests ../../scripts
cd app/backend && ./.venv/bin/ruff format --check . ../../tests ../../scripts
cd app/backend && ~/.local/bin/ty check
cd app/frontend && npx tsc --noEmit && npx eslint . && npx next build

게이트는 스텁으로 돌므로 유료 호출이 0건임. 실물 모델이 계약을 지키는지는 회차 도구가 잼.

도구무엇을 재는가
tests/harness/w_worker_round.py 격리 DB 에 세션을 만들고 워커를 실물 모델로 켜 파이프라인 전 구간을 관통시킴 (setup → run → verify). 단정 아홉을 자동 판정함.
tests/harness/contract_sampler.py 같은 전사문을 여러 번 호출해 파서 계약 위반율을 셈. --rescan 은 저장된 응답을 호출 0건으로 다시 셈.
tests/harness/scenario_null_probe.py 무대가 없는 전사문에서 모델이 무엇을 내는지 탐침함.
tests/harness/ws_session.py WebSocket 세션 하나를 끝까지 관측해 프레임을 기록함.
tests/harness/teardown_session.py 회차가 만든 세션과 그 job 을 걷음 — 남기면 앱 큐가 오염됨.
scripts/smoke_analysis.py 전용 스모크 DB 를 새로 만들어 분석·계획 경로를 실물 모델로 한 번 관통시킴.
scripts/check_doc_links.py 이 개요서와 색인 문서의 링크·경로 표기가 실재하는지 셈. 문서를 고친 뒤 돌림.

유료 회차는 격리 DB(ohmyenglish_worker)에서 돌림 — 개발 DB 에 픽스처 문장을 넣으면 학습자의 실제 오류 패턴과 복습 일정이 섞이고 그것은 되돌리기 어려움. 회차 증거는 tests/harness/runs/<날짜>-<이름>/ 에 남기고 노트를 그 옆에 둠.

8. 아직 없는 것

여기 적는 것은 「의도적으로 범위 밖」과 다름 — 만들려 했으나 아직 없는 자리임.

없는 것지금 무엇이 일어나나
무대를 고르는 화면 홈의 「업무 역할극」이 비활성임. 무대는 추천 회전과 intake 생성으로만 붙음
무대를 만들지 못했다는 알림 대화에 무대가 없으면 생성 job 이 첫 시도에 종결하고 화면에는 아무 말도 없음. 알릴지는 요구사항 쪽 결정이라 발명하지 않았음
요구사항 판정표의 v1.5·v1.6 절 추적표가 v1.4 까지만 덮음. 그 두 절은 요구 철회와 진입 한정이므로 구현 상태보다 범위 판단이 필요한 자리임
요구사항별 판정 스냅샷(현황 보고) 2026-09-06 판을 보관소로 옮겼음. 새 스냅샷은 사용자가 요구할 때 형식 규약대로 만듦 — 그 사이의 상태는 이 개요서와 원장이 답함
발음 채점 범위 밖임(PRD §5). 시범과 재발화 기록만 범위에 듦

이 문서를 고쳐야 하는 때: 기능이 늘거나 줄었을 때 · 실행 절차가 바뀌었을 때 · 문서가 보관소로 옮겨졌을 때. 고친 뒤에는 python3 scripts/check_doc_links.py 로 링크가 전건 실재하는지 확인함(2026-09-20 기준 85건 전건 실재).
