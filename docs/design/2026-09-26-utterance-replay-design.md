# 튜터 발화 다시 듣기 — 방식 결정 (`TASK-274`)

> 작성 2026-09-26 · 사용자 요청: 말풍선마다 [음성] 버튼(첨부 이미지 2) · 화면은 `TASK-273` 이 먼저 만들었음.

## 1. 결정

브라우저가 **이번 세션에서 이미 받은 튜터 음성**을 발화별로 메모리에 모아 두고, [음성]을 누르면 그것을 다시 재생함.
서버는 오디오를 저장하지 않음. 새 API 도 두지 않음.

## 2. 검토한 세 안

| 안 | 내용 | 판정 |
|---|---|---|
| A. 서버 보관 | Nova 출력 오디오를 발화별 파일로 저장하고 `GET …/audio` 로 줌 | 기각 — PRD `R10-7`(오디오 원본은 저장하지 않음)을 뒤집음. 예외는 쉐도잉 낭독 하나이고 011 의 CHECK(`utterances_audio_only_for_shadowing`)가 그 경계를 가둠. 뒤집는 것은 사용자 결정이 필요함 |
| B. TTS 재합성 | 전사문을 TTS(Polly 등)로 다시 만듦 | 기각 — 새 외부 서비스·권한·비용이 생김. 학습자가 들은 목소리와 달라짐 |
| C. 브라우저 메모리 | 받은 프레임을 발화별로 모아 재생 | 채택 — 저장 0 · 비용 0 · 같은 목소리 |

## 3. 짝짓기 근거 — 실측 순서

실물 Nova 녹화(`tests/unit/test_nova.py` 의 `RECORDED_RUN` · `runs/2026-08-26-N1`)에서 한 턴은
`TEXT(SPECULATIVE)` → `AUDIO` 블록 → 그 블록의 `contentEnd(stopReason=END_TURN)` 순서임.
어댑터는 `END_TURN` 에서 그 턴의 전사를 `final` 로 올림(`NovaEventTranslator._on_content_end`).
⇒ **직전 튜터 `final` 이후 받은 오디오 프레임은 전부 다음 튜터 `final` 의 것임.** tool 호출로 블록이 여럿이어도
`END_TURN` 은 마지막에 한 번 옴.

## 4. 감수한 한계

- **세션이 끝나면 사라짐.** 결과 화면·이력에서는 다시 들을 수 없음. 그 요구가 생기면 안 A 의 결정(`R10-7` 예외)이 선행되어야 함.
- **끊긴 턴(barge-in)은 브라우저가 받은 만큼 들림.** 끊기면서 재생 큐에서 버린 뒤쪽도 이미 받았으면 다시 듣기에는 들어감. 서버가 보내지 않은 뒤쪽은 없음.
- **음성 뒤에 튜터 `final` 이 오지 않으면 그 음성이 다음 튜터 줄에 붙음.** 저장 실패로 `final` 을 방송하지 못한 턴 · 글이 제어 페이로드뿐인 턴이 그 경우임. 드물다고 보고 막는 장치를 두지 않았음.
- **스텁 어댑터로는 이 기능을 판단할 수 없음.** 스텁은 `final` 을 먼저 보내고 음성을 나중에 보내므로 첫 줄은 비활성이고 이후 줄은 앞 턴의 음성을 받음. 판별은 실물 순서로 주입하는 방식으로 했음(`TASK-274` 노트).
- **다시 듣기는 진행 중인 코치 응답과 겹쳐 들릴 수 있음.** 재생 큐와 가르는 것이 의도이고(`VoiceIo.replayPcm` 주석), 겹침의 실사용 느낌은 아직 관측하지 않았음.
- 메모리: 16kHz·16bit·mono = 32KB/초. 튜터 발화 10분이 약 19MB 임.

## 5. 원장 수용기준의 변경

`TASK-274` 은 백엔드 태스크로 등록됐고 AC 에 `GET …/audio` 와 보존 기한이 있었음. 안 C 가 서버 표면을 두지 않으므로
그 두 AC 를 「브라우저 재생」·「저장 0」으로 바꿨음. 되돌리려면 이 문서 §2 의 안 A 기각 근거를 먼저 뒤집어야 함.
