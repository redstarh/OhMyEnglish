## 2. 사용자가 물은 넷 — 실재 여부부터 가른다

### TTS — ⛔ **제품 기능이 아니다. 테스트 음원 생성 도구다**

`README.md` 의 기능 표에 TTS 가 없다. 매칭 9건을 전부 열어 보니 **전부 테스트 픽스처 생성**
맥락이었고, 제품 기능으로서의 음성 출력은 *"양방향 번역 / TTS 송출 / 답변 추천"* 이
**범위 밖**으로 적힌 자리 하나뿐이다(`backlog/tasks/task-7 …md:32`).

### Qwen 3 — ✅ **`Qwen3-TTS` 를 로컬 MLX 로 돌려 테스트 음원을 만들었다. 실측치가 있다**

정본은 `backlog/tasks/task-20 …md:78~92` 다. 직접 읽어 옮긴다:

| 항목 | 값 |
|---|---|
| 모델 | `mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-bf16` |
| 라이선스 | **Apache-2.0** |
| 크기·성능 | 0.6B · 가중치 **2.3 GB** · **RTF 0.92x** · 최대 메모리 **5.25 GB** |
| 화자 | **9종 · 참조 오디오 불필요.** `Sohee` 가 한국어 원어민 여성 · `Aiden` · `Yuna` 도 등장 |
| 설치 | `uv pip install mlx-audio` (임시 venv) |

```bash
/tmp/qwen_tts_env/bin/python -m mlx_audio.tts.generate \
  --model mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-bf16 \
  --voice Sohee --lang_code ko --text '문장' --output_path /tmp/qwen_out --audio_format wav
```

⛔ **전사 정확도 실측 — 같은 문장 3개 · 같은 장치 구성**:
- `say -v Yuna`: **3문장 중 1문장이 원문과 어긋났다**(들어온 → 들어오니)
- `Qwen Sohee/Aiden`: **3문장 모두 텍스트가 일치**했다. 누락은 고유명사 1건뿐

⚠️ **그 프로젝트는 이것을 의존성에 넣지 않았다** — *"검증 전용이므로 임시 venv 로 격리했다"*.

### STT — AWS Transcribe Streaming. **OhMyEnglish 와 목적이 다르다**

`docs/design/tech-stack.md:135~147` 이 정본이다. 16000 Hz mono · `show_speaker_label=True`
(**final 결과에만 라벨이 온다**) · 언어 단일 코드(`en-US`/`ko-KR`, 자동 감지는 범위 밖) ·
⛔ **종료 시 빈 오디오 프레임을 보낸 뒤 close** — 그냥 close 하면 `BadRequestException`.
**번역은 Transcribe 가 하지 않는다** → Bedrock 별도 호출.

### 발음 평가 — ⛔ **없다**

`발음` 검색 **0건**. `pronunciation` 2건은 **Transcribe 의 item type**(`"pronunciation" | "punctuation"`
— 단어인지 구두점인지)이고 발음 품질과 무관하다(`src/realtime_meeting/stt/results.py:17`).
→ **발음 교정은 OhMyEnglish 고유 영역이고 가져올 것이 없다.**

## 3. BlackHole — ⛔ **OhMyEnglish 에 필요하지 않다. 코드로 확정했다**

**그 프로젝트가 왜 쓰는가**: 회의 **상대의 목소리**(시스템 오디오)를 잡아야 한다. macOS 브라우저는
시스템 오디오를 캡처할 수 없다는 것이 그 리포의 실측 함정이다(`docs/ops/pitfalls.md:38`).

**OhMyEnglish 는 왜 필요 없는가** — 근거 둘:

1. **학습자 자기 음성만 필요하다.** 앱이 내는 소리(코치 음성)를 되잡을 이유가 없다.
2. ⛔ **하네스가 마이크를 아예 거치지 않는다.** `tests/harness/scenarios-N-real-voice.md:154~163`
   이 `getUserMedia` 를 **합성 스트림으로 대체**한다 — WAV 를 `decodeAudioData` 로 디코드해
   `createMediaStreamDestination()` 으로 만든 스트림을 마이크처럼 돌려준다. **스피커·마이크·시스템
   오디오를 하나도 거치지 않는다.**

→ **BlackHole 설치·GPL-3.0 고려·`doctor` 채널 진단 전부 불필요하다.** ⚠️ 예외가 성립하는 유일한
경우는 「TTS 음원을 스피커로 재생해 실제 마이크로 받는」 방식인데, 그 프로젝트가 `headset` 모드에서
바로 그것을 하다 **결함 4건**(채널 귀속 오판정·`doctor` 오진·설정 덮임·partial 잔존)을 냈다
(`task-20` 의 「여기서 나온 결함」). **그 경로를 택하지 않는 것이 옳다.**

## 4. Fit — 적용할 것. 값어치 순

### F1 — **Bedrock prompt cache: ⛔ 조사 중에 「적용 불가」로 판정됐다. 근거를 남긴다**

⚠️ **이 절은 처음에 「가장 큰 Fit」으로 적었고 그 판단이 틀렸다.** 조사 중에 직접 재서 뒤집었으므로
**뒤집힌 사실과 근거를 함께 남긴다.**

**우리 현재 상태 — 코드로 확인했다**:
- `cache_control`·`cache_creation_input_tokens`·`cache_read_input_tokens` 가 앱 코드에 **0건**.
  즉 「캐시가 조용히 안 붙는다」가 아니라 **애초에 쓰지 않는다.**
- 호출은 boto3 **`invoke_model`**(비스트리밍) · **단일 `prompt` 문자열** · `system` 블록 없음
  (`app/backend/app/workers/claude_client.py:56` `build_invoke_body`). 그 파일 주석이 스스로
  *"토큰을 직접 다루지 않는다"* 고 적는다.
- **토큰 사용량을 어디에도 기록하지 않는다** — `analysis_jobs` 컬럼에 토큰 자리가 없다(직접 조회).

**⛔ 그리고 붙일 수 없다 — 프리픽스가 최소 길이에 못 미친다.** `build_prompt`
(`app/backend/app/services/analysis.py:182`)는 **고정 블록 7개를 앞에, 유동(기존 패턴·전사문)을
뒤에** 두는 좋은 모양이다. 그 고정 프리픽스를 직접 재니:

| 블록 | 문자 수 |
|---|--:|
| `_ROLE_AND_LEVEL` · `_CORRECTION_STYLE` · `_TARGET_FORM_RULES` · `_SUGGESTED_CONTEXTS_RULES` · `_CATEGORIES` · `_PATTERN_KEY_RULES` · `_ATTEMPT_RULES` | 합계 **2,469자** |

거친 추정으로 **617~1,646 토큰**이다(한국어 혼합이라 4자/토큰과 1.5자/토큰 사이).
⛔ **최소 캐시 프리픽스 4096 토큰에 크게 못 미치고, 그쪽이 실패를 관측한 2,426 토큰보다도 짧다.**
⚠️ **정확한 값은 API 응답의 `usage` 만이 진실이다** — 위 수치는 문자 수에서 유도한 추정이고
그것으로 「넘지 못한다」를 판정하기에는 충분하다(어느 비율을 써도 4096 에 못 미친다).

→ **캐시를 붙이려면 프롬프트를 4096 토큰까지 인위적으로 늘려야 하고, 그러면 ③(캐시 읽기도 시간을
쓴다 — 6600토큰에서 max 2354 ms 대 없을 때 1277 ms)이 그대로 우리에게 온다.** 즉 **품질과 무관한
팽창으로 지연과 비용을 사는 것**이라 지금 적용하지 않는다.

**그래도 남는 것 둘** — 캐시와 무관하게 값어치가 있다:

| # | 그 프로젝트가 실측한 것 | 우리 적용 |
|--:|---|---|
| 1 | **SDK 기본 타임아웃이 10분**이라 종료가 그만큼 늦어져 `8.0`s 를 명시하고 불변식으로 검사했다 | 우리 boto3 클라이언트의 타임아웃을 확인할 근거. 워커 종료 예산과 대조해야 한다 |
| 2 | 캐시 여부와 무관하게 **호출마다 토큰을 기록**했다(`llm_call`) — 예열 호출도 *"실제로 돈이 나가는 호출"* 이라 기록 | ⛔ **우리는 토큰을 기록하지 않는다.** 그래서 비용이 어디로 새는지 관측할 수단이 없고, 캐시 도입 여부를 나중에 재려 해도 **비교 기준선이 없다.** 이것이 이 조사에서 찾은 **가장 실질적인 빈자리**다 |

⚠️ 캐시 관련 나머지 셋(프리픽스 동일성 · 읽기 지연 · 예열)은 **우리가 캐시를 쓰게 되면** 되살아나므로
지우지 않고 여기 남긴다 — `docs/ops/pitfalls.md:203~247` 이 그 정본이다.

### F2 — **Qwen3-TTS 를 발음 픽스처 생성에 쓴다**. 우리 픽스처의 실제 병목에 닿는다

⛔ **우리가 지금 `say` 를 쓴다**: `tests/harness/scenarios-P-pronunciation.md:83~85` 가
`say -v Samantha`(정확·음소치환판) · **`say -v Yuna`(한국어 억양판)** → `afconvert` 로 16 kHz WAV.
현재 픽스처 9개(`u1`·`u2`·`u3`·`p1a`·`p1m`·`p1k`·`p2a`·`p2m`·`p2k`)가 그렇게 만들어졌다.

**그리고 그 픽스처가 목적을 달성하지 못한 것이 5차수에 실측됐다**:
- `P2(p2m)` **FAIL** — 전사가 복원되지 않고 왜곡됐다
- `P4(p1k)` **FAIL 미재현** — 한국어 억양 영어가 **영어로 정확히 전사**돼 오류가 재현되지 않았다
- `TASK-13` — *"표본이 늘지 않았다(4행 유지). **합성 픽스처로 늘릴 수 없음이 통제 대조로 확정**됐다"*
- DB 실측: `pronunciation_attempts` **4행 전부 `signal_source = nova_tool`** 이고
  `korean_transcript` 신호는 **0행**이다(`SignalSource` 는
  `Literal["nova_tool","korean_transcript","agent_reprompt"]` — `models/pronunciation.py:40`)

⛔ **realtime-meeting 이 잰 열등한 도구가 정확히 우리가 쓰는 `say -v Yuna` 다.** 그쪽에서 3문장 중
1문장이 어긋났고 Qwen 은 3/3 일치했다. **즉 우리 픽스처 실패의 일부가 도구 품질일 수 있다.**

**적용안**(비용 낮음 · 되돌리기 쉬움):
- 임시 venv 로 격리해 쓴다 — **프로젝트 의존성에 넣지 않는다**(그쪽 판단을 그대로 계승).
- 한국어 원어민 화자(`Sohee`)로 **영어 문장**을 읽혀 `p1k`·`p2k` 를 다시 만든다. 목적이
  「한국어 억양 영어」이므로 화자·언어코드 조합이 그 목적에 더 맞다.
- 화자 9종이 **참조 오디오 없이** 쓰이므로 `TASK-13` 이 막힌 「표본을 늘릴 수 없다」에 새 축이 생긴다.

⚠️ **이것은 검증되지 않은 가설이다 — §6 에 실험으로 남긴다.** Qwen 이 「정확한 발음」을 잘 낸다는
실측은 있지만 **「의도한 발음 오류」를 낼 수 있다는 증거는 없다.**

### F3 — **테스트 도구를 의존성에서 격리하는 규율**

*"프로젝트 의존성에 넣지 않았다 — 검증 전용이므로 임시 venv 로 격리했다"*(`task-20`).
우리 `tests/harness/` 가 `app/backend/.venv` 를 공유하므로 무거운 검증 도구(MLX·2.3 GB 가중치)를
넣으면 게이트·CI·배포에 전부 얹힌다. **격리가 규약이 될 자격이 있다.**

### F4 — **재생 도구의 소요 시간을 먼저 재라**

*"재생 도구의 소요 시간을 먼저 재지 않으면 앱 결함으로 오인한다 — 실제로 그렇게 오인했다"*
(`task-20:75`). 미설치 음성은 `say` 가 **0.016초** 파일을 만든다.
→ 우리 하네스도 픽스처 길이를 단정에 쓴다(`u1.wav` = 1,920 ms). **음원을 새로 만들면 길이를
먼저 재고 그 값을 단정에 넣어야 한다.**

### F5 — **Transcribe 종료 규약이 「스트림 종료」 부류의 참고가 된다**

*"종료: 빈 오디오 프레임을 보낸 뒤 close. 그냥 close 하면 `BadRequestException`"*
(`tech-stack.md:144`). ⚠️ **Nova Sonic 에 그대로 적용되지 않는다**(다른 API) — 다만 우리도
세션 종료 경로를 다루므로 **「닫기 전에 무엇을 보내야 하는가」를 확인할 질문**으로 남는다.

## 5. Gap — 가져오지 않는 것과 그 이유

| 항목 | 왜 맞지 않는가 |
|---|---|
| **BlackHole · `doctor` 채널 진단** | §3 참조. 하네스가 마이크를 거치지 않고 앱이 시스템 오디오를 쓰지 않는다 |
| **AWS Transcribe Streaming** | 단방향 전사다. OhMyEnglish 는 **양방향 대화**(Nova Sonic)가 요구사항이라 대체가 아니라 후퇴다 |
| **화자 분리(diarization)** | 학습 세션은 화자가 **둘로 고정**(학습자·코치)이고 채널로 이미 갈린다. 그쪽은 그것 때문에 결함 3건(`task-17`·`18`·`21`)을 안고 있다 |
| **SQLite (WAL) · FTS5 배제** | 우리는 PostgreSQL 공유 인스턴스다. *"FTS5 는 한국어 2글자 질의 실패로 배제"* 는 SQLite 고유 문제다 |
| **Jinja2 + 빌드 없는 프런트** | 우리는 Next.js 로 이미 갔고 결과 화면 계약이 그 위에 있다 |
| **회의록 생성(notes/)** | 산출물 성격이 다르다. 우리 대응물은 **학습 결과·복습 과제**이고 이미 있다 |
| **로컬 우선(P4)** | 우리는 이미 Bedrock·Nova 를 부른다. 그 원칙은 그쪽의 프라이버시 요구에서 나온 것이다 |
| **`AWS_BEARER_TOKEN_BEDROCK` 과 SSO 를 가르는 배선** | 우리도 **이미 안다** — 기억 `bedrock-auth-two-paths` 가 그 함정을 담고 있다. 새로 배울 것이 없다 |
