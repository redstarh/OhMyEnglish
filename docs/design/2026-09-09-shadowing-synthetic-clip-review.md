## 1. 요구사항이 요구하는 것 — 「원어민」은 요구가 아님

`PRD.md` 를 직접 읽어 옮김.

| 자리 | 원문 |
|---|---|
| §4-6 (핵심 기능) | 발화 녹음 기반 쉐도잉 과제 |
| §7 Shadowing & Content | 30~90초의 짧은 오디오·영상 클립을 문장 단위로 제공한다 |
| 〃 | 듣기, 따라 말하기, 녹음 비교, 본인 상황으로 바꿔 말하기 순서로 진행한다 |
| 〃 | 외부 영상은 메타데이터·링크만 보관하고 사용자가 선택한 콘텐츠만 과제로 사용한다 |
| §5 (비범위) | 무제한 YouTube 자동 수집·저작물 전체 저장 |

⛔ **「원어민」이라는 요구가 쉐도잉 서술에 없음.** 전수 검색에서 `원어민` 은 세 자리에만 나오고
**셋 다 비범위 문맥**임 — `PRD.md:39`·`PRD.md:158`·`requirements-summary.md:120` 이 전부
*"원어민 유사도 지표를 내지 않는다"* 를 말함. 즉 제품은 원어민 유사도를 **재지 않기로** 정했고,
클립 화자가 원어민이어야 한다고 정한 자리는 **한 곳도 없음.**

**따라서 `TASK-63` AC#1 의 답은 후자임** — 요구는 「원어민 발화를 따라 한다」가 아니라
**「클립을 듣고 따라 말하고 자기 녹음과 비교한다」** 임. 화자의 원어민성은 발명된 요구임.

⚠️ **다만 요구되는 것 하나가 확실함 — 들을 것이 있어야 함.** §7 이 「오디오·영상 클립」과
「듣기」를 명시하므로 **소리 없는 전사문만으로는 그 절을 만족하지 못함.**

**같은 도구가 한 자리에서는 기각되고 다른 자리에서는 성립함** — 근거가 지연이었기 때문임.

## 4. ⛔ `TASK-63` 설명의 전제가 틀렸음 — 스키마를 바꾸지 않고는 저장할 수 없음

`TASK-63` 이 *"합성음 클립은 저작권 문제를 피하는 길이고 **스키마를 바꾸지 않는다**"* 고 적었음.
`db/migrations/011_shadowing_items.sql` 을 직접 읽어 **뒤집었음.**

**`shadowing_items` 에 클립 오디오를 담을 컬럼이 없음.** 전체 컬럼은
`id`·`source_title`·`source_url`·`transcript`·`clip_start_sec`·`clip_end_sec`·`level`·`created_at` 임.
`source_url` 의 주석이 *"외부 영상은 **링크만** 보관한다"* 이므로 그 자리는 **출처 링크**이고
로컬 오디오 경로를 넣는 것은 의미 오버로드임.

**그리고 학습자 낭독 자리도 못 씀** — 스키마가 CHECK 로 막음:

```sql
alter table utterances
  add constraint utterances_audio_only_for_shadowing
  check (audio_url is null
         or (utterance_type = 'shadowing_recording' and speaker = 'user'));
```

그 위 주석이 의도를 직접 적었음: *"R10-7(오디오를 저장하지 않는다)의 예외 경계를 스키마에
새긴다 … **캡틴이 연 예외는 이 하나이고, 다른 오디오가 조용히 쌓이는 길을 여기서 막는다.**"*

⛔ **즉 합성음을 저장하는 것은 그 문장이 막으려고 만든 바로 그 길임.** `speaker = 'user'` 라
튜터·합성 오디오는 원리적으로 들어갈 수 없음.

### 4.1 R10-7 이 쉐도잉 클립까지 덮는가 — ⚠️ 해석 문제이고 단정하지 않음

R10-7 원문은 `PRD.md:147` 임: *"오디오 원본은 기본 저장하지 않는다(§8 유지). 남는 것은
**판정 결과와 시범 문장**이다"*. **그 줄이 있는 자리가 §10(발음 시범·재발화)임** —
쉐도잉은 §7 의 다른 기능임.

| | 사실 |
|---|---|
| R10-7 이 「시범 음성」을 덮는 것은 확실함 | `2026-08-27-pronunciation-echo-design.md:200` 이 *"시범 음성과 학습자 재발화 오디오를 저장하지 않는다"* 로 읽었음 |
| **§7 쉐도잉 클립까지 덮는지는 원문에 없음** | R10-7 은 §10 안의 조항이고 §7 을 가리키지 않음. `PRD.md:39` 의 「§10 은 채점이 아니라 범위에 든다」 같은 **경계 명시가 §7 방향으로는 없음** |
| 다만 구현의 의도는 넓게 막는 것이었음 | 위 CHECK 주석이 *"다른 오디오가 조용히 쌓이는 길을 여기서 막는다"* 라고 적었음 |
| 그리고 「기본」이라 절대 금지가 아님 | `2026-09-06-captain-decisions.md:74~75` 가 *"「기본」이므로 절대 금지가 아니었다 → 요구사항을 뒤집는 것이 아니라 예외를 연 것"* 으로 이미 판정했음 |

⛔ **따라서 정확한 서술은 이것임**: 합성음 클립을 저장하려면 ① **스키마 변경**(컬럼 또는 표)과
② **위 CHECK 를 넓히거나 다른 자리를 만드는 것**이 필요하고, ③ **그것이 R10-7 의 예외를 하나 더
여는 것인지 아니면 R10-7 밖의 일인지는 해석임.** 어느 쪽이든 ①②가 필요한 것은 같음.

> ### ✅ 그 해석이 닫혔음 — 결정 47 (2026-09-09)
>
> 캡틴이 §5 의 **B(미리 만들어 저장)** 를 고른 것이 **R10-7 예외를 하나 더 여는 승인**임.
> 근거: R10-7 원문이 *"오디오 원본은 **기본** 저장하지 않는다"* 이고 결정 6 이 이미
> *"「기본」이므로 절대 금지가 아니었다 → 예외를 연 것"* 으로 그 읽기를 확정했음.
> ⚠️ **열린 범위는 「합성한 쉐도잉 클립 오디오」 하나임** — 학습자 오디오의 기존 예외와 별개이고
> 다른 오디오가 들어오는 길을 여는 것이 아님. 그 경계를 스키마에 새기는 것이 `TASK-66` AC#2 임.
> 정본은 `docs/ops/captain-instruction-register.md` 의 결정 47 임.

⚠️ **위 ③ 을 「R10-7 예외가 필요하다」로 미리 단정하지 않은 이유를 남겨 둠**: 원문이 §10 안에
있고 §7 을 가리키지 않으므로 그 단정은 근거보다 넓었음. 반대로 「§7 이라 무관하다」도 단정하지
않았음 — 구현 의도가 넓게 막는 것이었기 때문임. **캡틴이 고른 것이 그 둘 중 앞쪽이었음.**

## 7. 클립 생성 절차 (AC#4)

### 7.1 도구와 격리

```bash
uv venv --python 3.12 /tmp/qwen_tts_env
VIRTUAL_ENV=/tmp/qwen_tts_env uv pip install mlx-audio
/tmp/qwen_tts_env/bin/python -m mlx_audio.tts.generate \
  --model mlx-community/Qwen3-TTS-12Hz-0.6B-CustomVoice-bf16 \
  --voice Sohee --lang_code en --text '<transcript 전문>' \
  --output_path /tmp/qwen_out --file_prefix <클립id> --audio_format wav
```

⛔ **프로젝트 의존성에 넣지 않음.** 생성은 **오프라인**이고 앱은 만들어진 파일만 읽음 —
이것이 §5 에서 B 가 A 보다 싼 이유임. 모델 캐시는 `~/.cache/huggingface`(2.3GB)에 남고
`/tmp` 의 venv 는 재부팅에 사라짐(다시 만들면 됨).

### 7.2 ⛔ 길이를 재서 시간 창에 넣음 — 선언값을 발명하지 않음

**실측(2026-09-09)**: 시드 1건의 전사문 6문장(`I usually wake up at seven.` …)을 `Sohee`·`en` 으로
합성했더니 **16.64초**(24 kHz mono)였음. 그런데 **그 시드가 선언한 시간 창은 `0.00~30.00` 임**
(`scripts/migrate.py:146~147`).

⛔ **즉 합성음을 쓰면 시드의 선언값이 곧바로 틀린 값이 됨.** 외부 출처 클립에서는
`clip_start_sec`·`clip_end_sec` 가 **출처 안의 위치**라 임의값이 성립하지만, 합성음에서는
**그 창이 곧 오디오 전체**라 실제 길이와 같아야 함.

절차:

```bash
afinfo <파일> | grep -i duration          # ⛔ 먼저 잰다
afconvert -f WAVE -d LEI16@16000 -c 1 <원본> <최종>   # 앱 재생 규격에 맞춤
```

- `clip_start_sec` = `0.00` · `clip_end_sec` = **잰 길이**
- ⛔ **미설치 음성·실패한 생성은 0.016초 빈 파일을 만듦.** 그것을 앱 결함으로 오인한 사례가
  참고 리포에 있음 — 길이가 1초 미만이면 생성 실패로 보고 다시 만듦

### 7.3 지켜야 하는 값역

| 값 | 제약 | 어디서 오는가 |
|---|---|---|
| `clip_end_sec - clip_start_sec` | **≤ 90** | `shadowing_items_span_within_limit` CHECK · PRD §7 이 정한 요구값 |
| `clip_end_sec` | `> clip_start_sec` | `shadowing_items_span_ordered` CHECK |
| `level` | `A1`·`A2`·`B1`·`B2`·`C1`·`C2` 중 하나 | CHECK · `learning_scenarios.level` 과 같은 값역 |
| `source_title` | 공백만이면 안 됨 | CHECK (`btrim` 길이 > 0) |
| `transcript` | 공백만이면 안 됨 | CHECK |
| `source_url` | **`null` 로 둠** | 합성음은 외부 출처가 없음. 주석이 *"null = 내장·직접 입력 자료"* 로 그 자리를 이미 정의했음 |

**90초를 채우려면 문장이 얼마나 필요한가** — 위 실측이 6문장·37낱말에 16.64초이므로
대략 **문장당 2.8초**임. 90초는 **30문장 안팎**이 됨. ⚠️ 그 길이에서 품질이 유지되는지는
재지 않았음(§8).

### 7.4 아직 정해지지 않은 것 — 절차를 여기서 끝내지 않는 이유

**오디오를 어디에 두고 무엇으로 가리키는지가 미정임.** `shadowing_items` 에 그 자리가 없기
때문임(§4). 컬럼을 하나 더하는 것인지 별도 표인지, 파일이 리포 안인지 밖인지는 스키마 태스크가
정함. 그것이 정해지면 위 절차의 마지막 줄(파일을 어디에 두는가)이 붙음.

## 8. 이 검토가 확인하지 못한 것

- **합성음을 실제로 들어보지 않았음.** 판정 근거는 Nova ASR 전사 일치이고 **사람 청취가 아님.**
  학습 적합성을 재려면 사람이 들어야 함
- **`Sohee` 외의 화자를 시험하지 않았음.** 화자 9종 중 영어에 더 맞는 것이 있을 수 있음
- **프론트의 클립 재생 경로를 읽지 않았음** — §5 의 A·B 비용 추정은 스키마와 요구사항만 근거임
- **길이 상한 90초를 합성으로 채울 때의 품질 저하를 재지 않았음.** 시험한 문장은 3~5초임
