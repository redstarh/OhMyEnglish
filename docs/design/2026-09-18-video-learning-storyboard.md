# 영상으로 배우기 — 스토리보드 (`TASK-160`)

> **사용자 지시 2026-09-18**: *"YouTube 영상 수집·추천 TASK 위한 준비 작업 … 영상을 수집해서, 내가
> 영상을 보며 공부하고, 쉐도잉하기 위한 수업이야 … 지금 구현한 앱의 별도 메뉴나 기능으로 분리하면
> 좋을 것 같아 … 구현을 바로 진행하지 말고, 설계 진행전 스토리보드를 만들고"* ·
> *"기능은 심플하고 너무 복잡하지 않게해"*
> 참고 앱으로 `langflix.io` 를 지정했음.
>
> **이 문서의 자리**: 설계서보다 앞임. 화면과 사용자 동작만 정하고 표·API·타입은 정하지 않음 —
> 그것은 `TASK-161` 설계서의 몫임.
>
> **근거의 정본**: `TASK-157`(langflix 분해) · `TASK-158`(정책·API 제약) · `TASK-159`(코드 구조).
> ⛔ 그 셋의 노트를 여기 옮겨 적지 않음 — `backlog task view TASK-158 --plain` 으로 봄.

## §1. 이 갈래가 무엇인가 — 한 문장

**사용자가 YouTube 링크를 붙여넣고, 영상을 보다가 안 들리는 구간을 담아 들은 대로 적고, 그 문장으로
쉐도잉 연습을 하는 갈래임.**

⛔ **자막을 읽는 갈래가 아님.** `TASK-158` 이 실측한 대로 남의 공개 영상 자막을 얻는 합법적 경로가
없고 스크래핑은 정책이 금지함. 그래서 **문장의 출처는 사용자의 귀**임. langflix 의 「이중 자막」을
베끼지 않고, 그 자리를 **딕테이션**이 대신함.

⚠️ **그 교환이 손해가 아님**: 받아 적기는 듣기와 쓰기를 함께 쓰는 학습이고, 적은 문장이 그대로
쉐도잉 재료가 됨. 자막을 읽으면 그 두 단계가 사라짐.

## §2. 학습 한 바퀴 — 사용자가 겪는 순서

```
대시보드
  └─ [영상으로 배우기] 를 누름
       │
       ▼
  영상 목록 (S2)
       ├─ 담아 둔 영상이 카드로 보임 (없으면 빈 상태 안내)
       ├─ [영상 추가] → 링크를 붙여넣음 → 제목·썸네일을 확인 → [담기]
       └─ 카드를 누름
            │
            ▼
       영상 학습 (S3)
            ├─ 영상이 임베드로 재생됨
            ├─ 안 들리는 자리에서 [구간 시작] → 듣고 → [구간 끝]
            ├─ 그 구간이 반복 재생됨
            ├─ 들은 대로 문장을 적고 [담기]
            ├─ 담은 문장이 아래 목록에 쌓임
            └─ 문장의 [연습하기] 를 누름
                 │
                 ▼
            쉐도잉 세션 (기존 화면 · 새로 만들지 않음)
                 └─ 따라 말하고 발음 판정을 받음
                      │
                      ▼
                 복습 큐 (기존 · 새로 만들지 않음)
```

**새로 만드는 화면은 둘뿐임** — 영상 목록과 영상 학습. 연습과 복습은 이미 있는 것으로 흘려보냄.

## §3. 화면 목록과 이동

| 화면 | 경로 | 새로 만드나 | 무엇을 하는 자리인가 |
|---|---|---|---|
| S1 대시보드 | `/` (기존) | 진입점 한 줄만 더함 | 「영상으로 배우기」로 들어가는 문 |
| S2 영상 목록 | `/videos` | ⭕ 새로 만듦 | 담아 둔 영상을 보고 고르고 새로 담음 |
| S3 영상 학습 | `/videos/[videoId]` | ⭕ 새로 만듦 | 영상을 보며 구간과 문장을 담음 |
| S4 쉐도잉 세션 | `/` 의 세션 화면 (기존) | ✖ 배선만 함 | 담은 문장으로 따라 말함 |

⛔ **화면을 셋 이상으로 늘리지 않음.** 「영상 추가」와 「담은 문장 목록」은 별 화면이 아니라
S2·S3 안의 패널임 — 사용자가 한 흐름 안에서 왕복하는 동작이라 화면을 갈면 이동만 늘어남.

⚠️ **전역 네비게이션 바가 앱에 없음**(`TASK-159` 1항). 그래서 S1 → S2 는 `next/link` 로 직접 잇고,
S2 → S1 은 기존 `HOME_LINK_LABEL` 관례를 따름. **네비게이션 바를 이 작업에서 만들지 않음** — 그것은
이 갈래의 요구가 아니라 앱 전체의 구조 변경임.

## §4. 화면별 상세

### S1 대시보드 — 진입점 한 줄

**사용자가 보는 것**: 대시보드 아래쪽 `추가 학습` 목록에 **일곱째 항목** 「영상으로 배우기」가 보임.

**사용자가 하는 것**: 그 항목을 누름 → `/videos` 로 이동함.

⛔ **다른 여섯 항목과 거동이 다름** — 나머지는 세션 소켓을 열지만 이것은 **화면 이동**임. 그래서
목록 자료구조가 「세션을 여는 것」과 「화면으로 가는 것」을 구분할 수 있어야 함(설계서가 정함).

⛔ **`업무 역할극` 칸을 쓰지 않음.** 그 칸은 무대 선택 화면의 부재를 가리키는 표식이고 소유가
`TASK-102`·`TASK-5` 임(`TASK-159` 의 재사용 금지 항목).

### S2 영상 목록 (`/videos`)

**사용자가 보는 것**

- 담아 둔 영상이 카드로 나열됨: 썸네일 · 제목 · 채널명 · **담은 문장 수**.
- 영상이 하나도 없으면 빈 상태 안내와 「영상 추가」만 보임.
- 화면 위에 「영상 추가」 입력줄: URL 을 넣는 칸과 [확인] 버튼.

**사용자가 하는 것**

1. URL 을 붙여넣고 [확인] → 제목·채널·썸네일이 **미리보기**로 뜸.
2. [담기] → 목록에 카드가 생김.
3. 카드를 누름 → S3 으로 이동함.
4. 카드의 [지우기] → 확인을 받고 지움.

**오류가 보이는 자리**

| 무엇이 틀렸나 | 사용자가 보는 것 |
|---|---|
| URL 형태가 아니거나 영상이 없음 | 「이 링크에서 영상을 찾지 못했어요」 — oEmbed 가 **400** 을 줌(`TASK-158` 10항) |
| 이미 담은 영상 | 「이미 담아 둔 영상이에요」 + 그 카드로 이동 |
| 네트워크 실패 | 「지금 확인할 수 없어요. 잠시 뒤 다시 시도해 주세요」 |

⛔ **지우기에서 문장을 함께 지울지가 갈림길임** — 담은 문장은 사용자가 만든 학습 자산이고 복습
기록이 그것에 매여 있음. 스토리보드의 판단은 **영상을 지워도 담은 문장은 남김**이고, 그 대가는
「출처를 잃은 문장」이 생기는 것임. 설계서가 이 판단을 확정함(§7 질문 1).

### S3 영상 학습 (`/videos/[videoId]`)

**화면이 위아래 둘로 나뉨.** 위는 영상, 아래는 담은 문장 목록임.

**위 — 영상과 구간 담기**

- YouTube 임베드 플레이어가 영상을 재생함. **컨트롤을 가리지 않음**(정책 III.I.6).
- 버튼 하나가 상태에 따라 바뀜: [구간 시작] → [구간 끝] → [다시 듣기].
- 구간이 정해지면 그 구간이 **반복 재생**되고, 아래에 문장 입력칸이 열림.
- 입력칸 옆에 [담기] · [구간 다시 잡기] · [취소].

**사용자가 겪는 순서**

1. 영상을 봄. 안 들리는 말이 나옴.
2. [구간 시작] 을 누름 — 그 순간의 재생 시각이 시작점이 됨.
3. 말이 끝나면 [구간 끝] 을 누름 — 그 시각이 끝점이 됨.
4. 그 구간이 **자동으로 반복 재생**됨. 몇 번이든 들음.
5. 들은 대로 문장을 적음. 확신이 없어도 적음 — 틀린 것은 연습에서 드러남.
6. [담기] 를 누름. 문장이 아래 목록에 쌓이고 구간 담기는 초기 상태로 돌아감.

**오류가 보이는 자리**

| 무엇이 틀렸나 | 사용자가 보는 것 |
|---|---|
| 구간이 90초를 넘음 | 「구간은 90초까지 담을 수 있어요」 — 스키마 CHECK 가 이미 강제함 |
| 끝점이 시작점보다 이르거나 같음 | 「구간 끝이 시작보다 뒤여야 해요」 |
| 문장이 비어 있음 | [담기] 가 눌리지 않음 |
| 영상이 임베드를 막았음 | 「이 영상은 앱 안에서 재생할 수 없어요」 + YouTube 로 여는 링크 — 플레이어가 `101`·`150` 으로 알림 |

**아래 — 담은 문장 목록**

- 문장 하나마다: 문장 · 구간(`0:42~0:51`) · [그 구간 듣기] · [연습하기] · [지우기].
- [그 구간 듣기] 는 위 플레이어를 그 구간으로 보내 반복 재생함.
- [연습하기] 는 그 문장으로 **기존 쉐도잉 세션**을 엶.

### S4 쉐도잉 세션 — 배선만 함

**사용자가 보는 것**: 기존 쉐도잉 화면과 같음(`ShadowingPanel`). 다만 **문장이 방금 담은 그것**임.

⛔ **여기가 유일하게 기존 코드를 고치는 자리임** — 지금 클립 선택은 자동임
(`_ATTACH_SHADOWING_CLIP_SQL` 이 「수준 일치 첫 행, 없으면 전체 첫 행」을 고름). **사용자가 문장을
지정하는 경로가 없음.** 그 경로를 여는 것이 이 갈래가 기존 코드에 요구하는 전부임.

⚠️ **영상 오디오를 쓰지 않음.** 쉐도잉의 시범 오디오는 지금도 합성물이고, 영상에서 담은 문장에는
오디오가 붙지 않음 — 스키마의 `shadowing_items_audio_only_for_synthetic` 이 그것을 **이미 막고 있음**
(`TASK-159` 2항). 사용자가 원음을 다시 들으려면 S3 의 [그 구간 듣기] 로 감.

## §5. 각 화면이 필요로 하는 데이터

⛔ **표 이름·컬럼·API 경로를 여기서 정하지 않음** — 설계서의 몫임. 여기 적는 것은 **화면이 없으면
그릴 수 없는 값**뿐임.

| 화면 | 화면에 들어오는 값 | 화면에서 나가는 값 |
|---|---|---|
| S2 목록 | 담은 영상마다 · 영상 식별자 · 제목 · 채널명 · 썸네일 URL · **담은 문장 수** | 새 영상의 URL · 지울 영상의 식별자 |
| S2 미리보기 | 붙여넣은 URL 로 얻은 제목 · 채널명 · 썸네일 URL | 담기 확정 |
| S3 위 | 영상 식별자(플레이어에 넘김) · 제목 | 구간 시작 초 · 구간 끝 초 · 사용자가 적은 문장 |
| S3 아래 | 담은 문장마다 · 문장 식별자 · 문장 · 시작 초 · 끝 초 | 지울 문장 식별자 · 연습할 문장 식별자 |
| S4 | 담은 문장 하나(기존 쉐도잉 화면이 이미 읽음) | 없음 |

**값의 성질 셋** — 설계가 갈라 다뤄야 함.

1. **사용자가 만든 것**: 문장 · 구간 시각. 이것이 학습 자산이고 정본임.
2. **YouTube 에서 온 것**: 제목 · 채널 · 썸네일. ⚠️ **정책이 30일 보관으로 제한함**
   (`TASK-158` 3항) ⇒ 설계가 갱신 또는 만료 경로를 가져야 함.
3. **식별자**: 영상 id. 사용자가 준 링크에서 뽑은 것이고 보관 제한과 무관함.

⚠️ **1 과 2 를 한 컬럼에 섞지 않음** — 섞으면 「30일 지난 것을 지워야 하는데 학습 자산이 함께 지워짐」이 됨.

## §6. 심플하게 유지하려고 뺀 것 — 근거를 함께 적음

사용자가 *"기능은 심플하고 너무 복잡하지 않게해"* 로 요구했음. 아래는 **뺀 것과 그 근거**임.

| 뺀 것 | 근거 |
|---|---|
| **영상 검색** | `search.list` 가 일일 100회 제한이고 API 키·쿼터 관리가 함께 들어옴. 링크 붙여넣기로 학습이 성립함 — langflix 의 주 문구도 링크 하나임 |
| **영상 추천** | PRD §5 가 「무제한 자동 수집」을 비범위로 둠. 추천을 하려면 수집이 선행됨 |
| **이중 자막** | ⛔ 원리적으로 불가함 — 자막 취득 경로가 없음(`TASK-158`). 그 자리를 딕테이션이 대신함 |
| **낱말 사전·뜻 조회** | 외부 의존이 하나 더 늘고, 이 앱의 학습 목표는 말하기임 |
| **쓰기 퀴즈** | 딕테이션이 이미 쓰기를 겸함 |
| **난이도 자동 계산** | 고른 영상이 곧 난이도라는 langflix 의 판단을 따름. 담은 문장의 수준은 `users.current_level` 을 기본으로 씀 |
| **재생 속도 조절 UI** | YouTube 플레이어가 이미 가짐. 우리가 만들면 기능이 겹치고 정책 III.I.6(플레이어 기능 차단 금지)에 가까워짐 |
| **재생목록·채널 단위 담기** | 영상 한 개로 학습이 성립함. 담는 단위를 늘리면 목록·동기화가 함께 늘어남 |
| **딕테이션 자동 채점** | 정답이 없음(자막이 없으므로). 채점 대신 **쉐도잉 연습**이 틀린 것을 드러냄 |
| **월간 분석·다중 사용자** | 이 갈래의 요구가 아님. 미구현 목록의 다른 항목임 |

⛔ **뺀 것을 화면이 숨기지 않음** — 없는 기능의 버튼을 두지 않음. `TASK-128.4` 가 같은 부류의 결함
(「없는 기능의 진입 안내가 거짓이 된다」)을 이미 등록해 뒀음.

## §7. 이 스토리보드가 설계서에 넘기는 질문 다섯

⛔ **여기서 답하지 않음.** 설계서가 답하고 그 근거를 적음. 사용자가 부재하므로 설계서는 **권고로
답하고 되돌리는 비용을 함께 적음**.

1. **영상을 지울 때 담은 문장을 함께 지우나** — 스토리보드의 판단은 「남김」임(복습 기록이 매여 있음).
   대가는 출처를 잃은 문장이 생기는 것임. 설계가 그 문장을 화면에서 어떻게 다룰지 정해야 함.
2. **제목·채널·썸네일의 30일 보관 제한을 어떻게 지키나** — 저장하고 갱신할지, 아예 저장하지 않고
   화면을 열 때마다 받을지. 후자가 단순하지만 목록 화면이 영상 수만큼 외부 호출을 함.
3. **담은 문장의 `level` 을 무엇으로 채우나** — `users.current_level` 을 그대로 쓸지 사용자가 고르게
   할지. 스키마는 `A1`~`C2` 를 요구함(NOT NULL).
4. **구간 시각의 정밀도** — 스키마가 `numeric` 임. 소수 몇 자리까지 받고 반올림을 어디서 하나.
5. **대시보드 항목의 자료구조를 어떻게 넓히나** — 지금 `ADDITIONAL_LEARNING` 의 원소는 「세션을 여는
   것」을 전제함. 화면 이동 항목을 넣으려면 그 타입이 갈려야 하고, ⛔ **`업무 역할극` 의 빈 칸 표식이
   그 변경에 휩쓸리지 않아야 함**.

## §8. 이 스토리보드로 확인한 것 하나

**새로 쓰는 코드가 적음.** 화면 둘 · 라우터 하나 · 서비스 하나 · 표 하나 · 기존 함수에 인자 하나임.
연습·발음 판정·복습·오디오 재생은 **이미 있는 것이 그대로 받음.**

⚠️ **그 이유는 우연이 아님** — PRD §10 이 *"외부 영상은 메타데이터·링크만 보관하고 사용자가 선택한
콘텐츠만 과제로 사용한다"* 로 이 갈래를 이미 예고했고, `shadowing_items` 가 `source_url`·
`clip_start_sec`·`clip_end_sec` 를 그때 함께 만들어 뒀음. **이 작업은 새 기능을 얹는 것이 아니라
비어 있던 그 자리를 채우는 것임.**
