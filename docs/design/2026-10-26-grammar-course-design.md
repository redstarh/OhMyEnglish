# 문법 코스 설계 — Grammar in Use BASIC 이어 듣기와 한 문장 따라 말하기 (`TASK-286`)

> 상태: 사용자 승인(2026-10-26, 「현재 스토리보드 기준으로 구현」) · 스토리보드 v3 는
> `docs/design/2026-10-26-grammar-course-storyboard.html` 에 사본을 둠.

## 1. 의도

학습자는 어샷영어 채널의 Grammar in Use BASIC 영상 6편(Day 1~6, 단원 113개)을 처음부터 끝까지
틀어 놓고 이어 들음. 다음 날에는 멈춘 자리부터 다시 들음. 학습자는 그 단원의 문법 패턴으로 쓴 문장을
한 문장씩 보고 따라 말하며, 자기가 말한 문장을 화면에서 바로 확인함.

## 2. 목표 · 비목표 · 반목표

목표
- 학습자는 Day 를 고르고 멈춘 자리(영상 위치·단원·문장 번호)부터 이어서 학습할 수 있어야 함.
- 시스템은 문장을 한 번에 하나만 보여 주고 읽어 줘야 함.
- 시스템은 학습자가 따라 말한 문장을 전사해 원문과 낱말 단위로 견줘 보여 줘야 함.
- 학습자는 자동 모드와 수동 모드를 고를 수 있어야 함.
- 시스템은 날짜별 따라 하기 횟수를 히트맵으로 보여 줘야 함.

비목표
- 시작 화면의 「이어서 듣기」 카드(스토리보드 v1 장면 ①)는 만들지 않음. 사용자가 화면 2개로 줄였음.
- 복습 일정(1·3·7일) 연결은 이번 범위가 아님.
- 영상 위치에 맞춰 문장을 자동으로 바꾸는 동기화는 단원 경계 판정까지만 함.

반목표 — 이것이 생기면 실패임
- 영상 스크립트 원문을 저장하거나 그것을 한두 낱말만 바꾼 문장을 저장함. 교재 원문 복제가 됨.
- 영상의 오디오를 내려받거나 저장함.
- 학습자의 녹음 파일을 남김. 전사문만 남김.

## 3. 결정 (사용자)

1. 화면은 둘임: 학습 화면(`/course/[day]`) · 학습 목록 화면(`/course`).
2. 학습 화면은 문장 하나를 보여 주고, 학습자가 따라 말하면 그 문장을 아래에 표시함.
3. 학습 이력은 날짜별 히트맵으로 둠.
4. 자동 모드: 한 문장을 읽어 주고, 문장 길이만큼 기다린 뒤 다음 문장으로 넘어감. 수동 모드도 둠.
5. 문장은 원문이 아니라 단원의 문법 패턴으로 새로 쓴 문장임(원문·한 낱말 변형은 저작권 문제로 거절).

## 4. 내가 정한 것 (빌더 판단 · 검토 대상)

- 문장 음성은 브라우저 내장 음성 합성(Web Speech API `speechSynthesis`)으로 읽음.
  근거: 기존 합성 클립은 미리 만든 WAV 파일이라 문장 565개면 리포에 약 45MB 가 들어감.
  음성 합성을 못 쓰는 브라우저에서는 낱말 수로 길이를 어림함(낱말당 0.4초).
- 자동 모드의 대기 시간은 「실제로 읽어 준 시간 + 1초」임. 그 시간 동안 마이크를 염.
  대기가 끝나면 전사를 기다려 결과를 보인 뒤 1.5초 후 다음 문장으로 넘어감.
- 전사·비교는 기존 `create_transcriber` 와 `compare_readback` 을 그대로 씀.
  WebSocket 세션 없이 HTTP 한 번(`POST /api/course/sentences/{key}/attempts`, 원시 PCM)으로 처리함.
  전사기를 못 쓰는 설정(`VOICE_ADAPTER=stub`)에서는 503 이고, 화면은 「지금은 판정을 쓸 수 없어요」를
  보인 채 흐름을 이어 감.
- 반복 횟수는 「문장을 따라 말한 횟수」(시도 행 수)로 셈. 전사가 비어도 시도로 셈.
- 회차는 「6편 모두 끝낸 횟수 + 1」임. Day 완료는 영상이 끝까지 재생됐거나 마지막 문장을 마쳤을 때임.
- 모드 선택은 브라우저 `localStorage` 에 둠(단일 사용자 로컬 도구).
- 영상 위치는 재생 중 5초마다, 그리고 화면을 떠날 때 저장함.

## 5. 데이터

콘텐츠(정적, 리포의 파일): `app/backend/app/content/grammar_basic.json`
- Day 6개: `day`, `youtube_id`, 단원 목록.
- 단원: `unit`, `topic`(내가 쓴 짧은 한국어 이름), `start_sec`, `end_sec`(영상 목차에서 옴), 문장 5개.
- 문장 키는 `u027-s2` 처럼 단원·순번으로 정함 — 바뀌지 않는 키라 시도 기록이 가리킬 수 있음.
- 영상 제목·채널명은 담지 않음(YouTube 정책 III.E.4 의 30일 보관 제한을 피함). 영상 ID·시각은 사실 정보임.

DB(마이그레이션 033, 스키마 `ohmyenglish`)
- `course_day_progress`: `user_id`, `day`(PK 짝) · `position_sec` · `unit` · `sentence_index` ·
  `completed_count` · `last_completed_at timestamptz` · `updated_at timestamptz`.
- `course_attempts`: `id` · `user_id` · `sentence_key` · `transcript` · `words jsonb` ·
  `created_at timestamptz default now()`. 날짜 버킷은 `(created_at at time zone users.timezone)::date`.

## 6. API

- `GET /api/course` → Day 목록(단원 범위·길이·진도·완료 횟수) · 회차 · 날짜별 시도 수(최근 16주) ·
  최근 날짜 표(Day·단원 범위·문장 수·횟수).
- `GET /api/course/days/{day}` → Day 콘텐츠(단원·문장) + 저장된 진도 + 문장별 누적 횟수.
- `POST /api/course/days/{day}/progress` → `position_sec`·`unit`·`sentence_index`·`completed`(선택).
  `PUT` 이 아닌 이유: CORS 허용 메서드가 `GET`·`POST`·`DELETE` 이고 메서드 하나를 위해 넓히지 않았음.
- `POST /api/course/sentences/{key}/attempts` (본문: PCM 16kHz·16bit·mono, 최대 30초) →
  `{transcript, words, attempts}`. 전사기 없음 503 · 키 없음 404 · 빈 본문·초과 413/422.

## 7. 화면

- `/course`: Day 목록(진행 중 Day 강조 · 「이어서 학습」) · 히트맵(칸=하루, 4단계 색) · 최근 날짜 표.
- `/course/[day]`: 위에 YouTube 플레이어(저장 위치부터) · 지금 단원 이름 · 문장 카드(번호/5 ·
  누적 횟수 · 단계 표시 · 대기 막대 · 「내가 말한 문장」) · 「이전·다시·다음 문장」 · 「자동|수동」.
- 문장 연습이 도는 동안 영상은 멈춤(마이크가 영상 소리를 받지 않게). 영상을 다시 재생하면 연습은 멈춤.
- 추가 학습 메뉴에 「문법 코스」 항목(`href: /course`)을 더함.
- 사용자 결정(2026-11-01 · `TASK-289`): 저장 위치가 있는 Day 를 열면 영상은 그 자리로 옮겨 멈춰 둠.
  재생은 학습자가 시작함. 근거는 열자마자 소리가 나지 않고 문장 연습과 스피커를 다투지 않는 것임.
- 사용자 결정(2026-11-01 · `TASK-289`): 「내가 말한 문장」의 밑줄·취소선은 원문 낱말에 침.
  근거는 기존 쉐도잉 판정과 같은 규칙을 지키는 것임. 스토리보드 그림(학습자 낱말에 밑줄)과 다름.
