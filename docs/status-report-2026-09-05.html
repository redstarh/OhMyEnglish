가장 중요한 한 문장: 부분(20건)이 완료(17건)보다 많고, 그 부분의 대다수가 같은 이유다 — 계산·저장은 되는데 읽는 코드가 0곳이다. 복습 큐·계획 질문·수준·추천 이유가 전부 값을 만들지만 화면도 세션 시작도 그것을 읽지 않는다. 직접 확인: session_plans를 select하는 코드가 app 안에 0건. 이 한 칸을 잇는 것이 슬라이스 2의 남은 절반(S2-8~S2-11)이다.

미결정 — 사람의 결정을 기다린다 (8건)

#무엇을 결정하나왜 지금 막혀 있나
1⏸ 007을 실물 dev DB에 적용되돌리기 어렵다. 안 했기 때문에 오염된 입력으로 만든 계획이 존재하지 않는 상태가 유지된다 (S2-L1)
2⏸ 실물 Claude로 계획 생성 1회비용이 든다. 자동 테스트는 전부 대역이라 실물 왕복 0회가 남는다 (S2-L2)
3⏸ target_sound 값역이 §10 의도와 어긋나는가관측 3건에 음소 치환이 하나도 없다(am_as_i_m=축약형, an_as_a=관사) — 발음이 아니라 문법에 가깝다. 표본이 작아 마이크 세션이 더 필요하다 (I-2)
4⏸ 발음 pattern_key 값역을 열거해 고정할까실물 관측이 부족해 표시 사전을 만들면 발명값이 굳는다. 3번과 같은 뿌리라 함께 판정해야 한다
5⏸ toolResult 미반환의 다중 턴 안전성1회 관측만 있고 미검증(발음 설계서 §9 미결 1)
6⏸ review_tasks 행의 정체성 경계재계산이 delete+insert라 id·status가 매번 초기화된다. 지금 reader 0곳이라 무해하지만 UI가 과제 id로 "완료 표시"를 하기 전에 정해야 한다
7⏸ AC11-5를 언제 닫을까실물 음성 응대가 달라지는 것을 요구해 슬라이스 2 밖으로 이월됐다
8⏸ git remote 생성·연결git remote -v가 비어 있어 푸시할 대상이 없다. 리포 생성은 캡틴 몫이다
미결정과 구분해야 할 것 — 이미 결정된 축소 2건. 되돌릴 대상이 아니다: agent_reprompt(되묻기 문구 감지)는 문구 매칭이라 케이스가 불어나 만들지 않는다 · 교정 예산은 코드 강제 없이 프롬프트로만 한다(설계서 §8 D5-1). 발음 패턴이 복습 스케줄에 들어오지 않는 것도 알고 남긴 축소다(설계서 §4.1 「구현 공백 4」) — 버그로 다시 조사하지 말 것.
