# PRD — OhMyEnglish · **v1.1** (개정 이력 §12 · 이전 판 사본 `docs/backup/v1.0/PRD.md`)

## 1. 제품 정의

OhMyEnglish는 사용자의 음성 영어 발화를 분석하고, 반복 오류를 패턴 단위로 저장해 다음 학습에 반영하는 개인화 Speaking Agent다. 일상 대화와 반복 질문·답변을 매일 훈련하며, 장기적으로 IT 프로젝트 리딩·보고 영어를 지원한다.

## 2. 문제와 사용자

**대상 사용자:** 일상적인 단문 대화는 가능하지만, 시제·어순·전치사·업무 표현에서 같은 실수를 반복하며 긴 설명과 회의 발화에 부담을 느끼는 한국어 화자.

**해결할 문제**

- 대화 중 교정은 받지만, 다음 학습에서 같은 오류가 다시 연습되지 않는다.
- 문법 학습과 실제 말하기가 분리되어 있다.
- 업무 상황에서 즉시 쓸 수 있는 표현을 체계적으로 연습하기 어렵다.

## 3. 목표와 성공 지표

| 목표 | 지표 |
|---|---|
| 매일 말하기 습관 형성 | 주 4회 이상, 세션당 10분 이상 |
| 반복 오류 감소 | 상위 3개 오류 패턴의 4주 재발률 30% 이상 감소 |
| 업무 보고 자신감 향상 | 4주차에 60초 상태 보고 완주 |
| 개인화 적합성 | 사용자 피드백상 복습 추천 적합 4/5 이상 |

## 4. MVP 범위

1. 음성/텍스트 기반 역할극과 전사문 표시
2. 세션당 핵심 오류 1~2개 교정
3. 오류 패턴 저장, 숙련도·다음 복습일 계산
4. 일간 복습 큐와 주간 학습 리포트
5. 일상 대화, 반복 질문·답변 드릴, IT 업무 업데이트 역할극
6. 발화 녹음 기반 쉐도잉 과제
7. 일일 목표 달성 뒤의 자유 추가 학습
8. UI와 음성 명령을 모두 통한 학습 제어

## 5. 비범위 (MVP 이후)

- 공인 발음 시험 수준의 음소 단위 채점 — 점수·등급·원어민 유사도 지표를 내지 않는다. **단 §10의 "올바른 발음 시범과 재발화 기록"은 채점이 아니므로 범위에 든다** (v1.1에서 경계 명시)
- 무제한 YouTube 자동 수집·저작물 전체 저장
- 실제 회사 문서/회의록 자동 전송
- 다수 학습자 경쟁 기능

## 6. 핵심 사용자 여정

1. 사용자가 오늘의 10분 Speaking 세션을 시작한다.
2. Agent가 짧은 상황을 제시하고 자연스럽게 대화한다.
3. 종료 후 Agent는 가장 영향이 큰 오류 1~2개와 좋은 표현을 알려준다.
4. 오류는 패턴으로 저장되고, 사용자는 즉시 변형 문장으로 다시 말한다.
5. 다음 세션은 미복습·고빈도 패턴과 업무 목표를 고려해 생성된다.
6. 일일 권장량을 채운 뒤에도 사용자는 원하는 모드로 추가 세션을 시작한다.
7. 주말에는 약점·개선·다음 주 계획을 보여준다.

## 7. 기능 요구 사항

### Speaking Coach

- CEFR A2 안팎의 문장 길이에서 시작하고, 성공률에 따라 난이도를 조절한다.
- 사용자 발화 비중은 전체 세션의 65% 이상을 목표로 한다.
- 한 번에 하나의 질문만 한다. 사용자가 막히면 선택지·힌트를 제공한다.
- 교정은 “원문 → 더 자연스러운 문장 → 한 줄 이유 → 2회 변형 발화” 순서다.
- 매일 최소 한 번은 일상 주제의 짧은 질문·답변 드릴을 제공한다. 같은 목표 문형을 3~5개의 다른 질문에서 사용하게 한다.
- `daily_goal`은 학습을 멈추게 하는 한도가 아니라 습관 형성을 위한 권장량이다. 완료 후에도 사용자는 즉시 추가 학습을 시작할 수 있다.

### Daily Conversation & Q&A Drills

- 주제: 인사, 하루 일과, 식사, 취미, 약속, 감정, 길 묻기, 작은 부탁, 의견 말하기.
- 매 드릴은 `질문 듣기 → 답변하기 → 짧은 후속 질문 → 다른 표현으로 다시 답하기`의 4턴 이상으로 구성한다.
- 같은 패턴은 일상 문맥부터 연습한 뒤 업무 문맥으로 전이한다. 예: `I need to...` → “I need to buy groceries.” → “I need to finish the test report.”
- 사용자는 “질문 더 주세요”, “이 패턴으로 연습 만들어줘”라고 요청해 즉시 드릴을 생성할 수 있다.

### Additional Learning

- 대시보드에 일일 권장량 완료 여부와 무관하게 항상 `추가 학습` 진입점을 제공한다.
- 추가 학습은 `자유 대화`, `약점 패턴 집중`, `질문 답변 5개`, `업무 역할극`, `쉐도잉` 중 선택한다.
- 추천 과제와 자유 과제를 모두 학습 이력에 저장하되, 권장량과 구분해 번아웃 분석에 사용한다.
- 피로를 감지하면 종료를 제안할 수 있지만, 사용자의 요청을 막지 않는다.

### Voice Control

- UI 버튼과 동일한 행동을 음성 명령으로 수행할 수 있다.
- 지원 명령: 학습 시작/계속/추가 학습, 모드 변경, 반복, 천천히 말하기, 힌트 요청, 다음 문제, 일시 정지, 종료, 복습·리포트 보기.
- 음성 명령은 한국어와 간단한 영어를 모두 지원한다. 예: “추가 연습 시작”, “질문 다섯 개 더”, “Repeat that slowly.”
- 학습 답변과 명령이 혼동되지 않도록 명령 모드 버튼과 시각적 마이크 상태를 제공한다. 세션 중에는 “Oh My English, …” 또는 명령 버튼을 통해 제어 발화임을 표시한다.
- 학습 종료·녹음 삭제 등 결과가 큰 명령은 음성으로 한 번 더 확인한다.

### Error Memory & Review

- 오류를 `시제`, `관사`, `전치사`, `어순`, `동사 형태`, `업무 표현`, `발음/억양`으로 분류한다.
- 원문이 아니라 재사용 가능한 패턴과 상황을 저장한다.
- 오류 빈도, 최근성, 영향도, 자가 난이도를 사용해 복습 우선순위를 정한다 — 조회는 이 **사실**들을 제공하고 **판단은 학습 분석 Agent**가 한다(v1.1: 가중치 공식을 제품이 발명하지 않는다. §11 R11-8).
- 같은 패턴을 최소 세 개의 다른 상황에서 재사용한다.

### Business English

- 시나리오: daily update, blocker 공유, 일정 변경, 우선순위 조율, incident update, stakeholder 보고.
- 상태 보고는 Status / Change / Risk / Decision needed / Next step 구조를 기본으로 한다.

### Shadowing & Content

- 30~90초의 짧은 오디오·영상 클립을 문장 단위로 제공한다.
- 듣기, 따라 말하기, 녹음 비교, 본인 상황으로 바꿔 말하기 순서로 진행한다.
- 외부 영상은 메타데이터·링크만 보관하고 사용자가 선택한 콘텐츠만 과제로 사용한다.

## 8. 비기능 요구 사항

- 오류 기록과 녹음은 사용자가 열람·수정·삭제할 수 있어야 한다.
- 업무 발화는 기본적으로 개인 학습 데이터로만 처리한다.
- Agent 응답은 음성 대화에서 짧고 즉시성 있게 유지한다.
- 교정 근거, 난이도 선택, 추천 이유를 UI에서 확인할 수 있어야 한다.
- 실시간 음성 대화의 기본 모델은 Nova Sonic, 오류 분석·장기 학습 계획은 Claude on Bedrock으로 분리한다.
- 음성 응답 경로에서 장기 분석을 동기 호출하지 않는다. 확정 전사문을 비동기 분석해 다음 턴·다음 세션에 반영한다.

## 9. 수용 기준 예시

- 사용자가 “Yesterday I work on API”라고 말하면, Agent는 과거 시제 오류를 기록하고 “Yesterday, I worked on the API.”를 말하게 한 뒤 새로운 업무 문장 두 개에서 같은 시제를 연습시킨다.
- 주간 화면에서 상위 오류, 개선 패턴, 다음 주 추천 시나리오를 확인할 수 있다.
- 4주차 사용자는 60초 동안 프로젝트 상태·리스크·다음 행동을 포함해 보고하고, Agent가 구조와 언어를 구분해 피드백한다.

## 10. 발음 시범·재발화 (v1.1 신설)

### 10.1 왜 필요한가 — 실측으로 확인된 공백

§4-6·§7이 "발화 녹음 기반 쉐도잉"과 "발음/억양 오류 분류"를 이미 요구하는데, 실제로 동작하는 것은 없다. 2026-08-26 하네스 4차수가 앱 경로로 실측해 확정했다(근거: `tests/harness/runs/2026-08-26-run-4.md` §P계층).

| 실측 사실 | 뜻 |
|---|---|
| 학습자가 목표음을 치환해 발음해도 ASR이 원문으로 복원한다 | 전사문에 발음 오류의 흔적이 **0**이다 |
| 그래서 전사문만 받는 분석 경로는 발음을 판정할 수 없다 | 원리적 한계다. 구현 실수가 아니다 |
| 오디오를 직접 듣는 실시간 음성 모델도 발음을 지적하지 않았다 | 지시문에 발음 규칙이 없기 때문이다 |
| 강한 억양은 전사문을 한국어로 뒤집는다 | 학습 가치가 0인 세션이 된다 |

결과적으로 **학습자는 "잘못 말했는데 아무 피드백이 없는" 세션을 받는다.** §3의 성공 지표 "반복 오류 감소"가 발음에 대해서는 측정조차 되지 않는다.

### 10.2 요구사항

| # | 요구사항 |
|---|---|
| **R10-1** | 학습자의 발음이 불명확하거나 목표음에서 벗어났다고 판단되면, Agent는 **올바른 발음으로 해당 문장을 다시 읽어준다.** 틀린 소리를 함께 지목한다 |
| **R10-2** | 시범 뒤 학습자에게 따라 말할 기회를 준다. 재발화 결과를 `성공 / 실패 / 판정불가` 세 값으로 기록한다 |
| **R10-3** | 발음 판정 주체는 **오디오를 직접 듣는 실시간 음성 모델**이다. 전사문 기반 분석 경로는 발음을 판정하지 않는다(§10.1의 원리적 한계) |
| **R10-4** | 판정 보조 신호 2개를 관측·기록한다 — ① 전사문에 한국어가 섞인 경우 ② Agent가 재요청을 발화한 경우. 보조 신호는 판정을 대체하지 않고, 모델이 놓친 경우를 다음 세션 계획이 볼 수 있게 남긴다 |
| **R10-5** | 일반 세션에서 발음 개입은 문법 교정과 예산을 다투지 않는다 — **보조 신호가 뜬 경우에만** 즉시 개입한다. 발음 집중 연습은 §7 Additional Learning 메뉴의 독립 항목으로 둔다 |
| **R10-6** | 발음 오류도 재사용 가능한 패턴으로 저장해 이후 학습에 재등장한다(§11 R11-9) |
| **R10-7** | 오디오 원본은 기본 저장하지 않는다(§8 유지). 남는 것은 **판정 결과와 시범 문장**이다 |
| **R10-8** | 발음 개입이 일어나도 §7의 "한 턴에 최대 1~2개 교정"과 "사용자 발화 65%"를 깨지 않는다 |

### 10.3 비범위 — §5와의 경계

우리가 하는 것은 **시범과 재발화 기록**이고, 하지 않는 것은 **채점**이다.

| 하는 것 (범위) | 하지 않는 것 (§5 비범위) |
|---|---|
| 올바른 발음으로 문장 재현 | 음소 단위 점수 |
| 재발화 시도의 성공·실패 기록 | 발음 CEFR 등급 |
| 발음 약점을 다음 세션 초점으로 재등장 | 원어민 유사도 지표 |
| 보조 신호(한국어 전사·재요청) 기록 | 오디오를 분석 경로로 보내는 채점 파이프라인 |

### 10.4 수용 기준

- **AC10-1** Given 학습자가 목표음을 치환해 발화했을 때, When Agent가 발음 개입을 하면, Then 올바른 발음으로 **문장 전체**를 다시 읽어주고 따라 말하기를 요청한다.
- **AC10-2** Given 재발화가 끝났을 때, Then 그 시도의 결과가 기록되어 **다음 세션 계획이 읽을 수 있다**.
- **AC10-3** Given 강한 억양으로 전사문이 한국어가 되었을 때, Then 그 사실이 보조 신호로 기록되고 **분석 파이프라인은 실패하지 않는다**.
- **AC10-4** Given 한 턴에 문법 오류와 발음 오류가 함께 있을 때, Then 개입은 §7 규칙대로 1~2건을 넘지 않는다.
- **AC10-5** Given 학습자가 추가 학습에서 발음 집중을 선택했을 때, Then 그 세션은 발음 시범·재발화를 주 활동으로 진행한다.

## 11. 학습 이력 기반 추천 학습 루틴 (v1.1 신설)

### 11.1 왜 필요한가 — 저장은 되고 활용은 안 된다

§6-5가 "다음 세션은 미복습·고빈도 패턴과 업무 목표를 고려해 생성된다"를 이미 요구한다. 4차수 M계층 실측이 그 미구현을 확정했다(근거: `run-4.md` §M계층).

- 오류 패턴이 8개 쌓인 뒤에도 세션 시나리오가 **고정 첫 행 하나**였다.
- Agent 응답이 패턴이 훨씬 적던 이전 세션과 **동일**했다.
- `복습 과제`가 0행, `다음 복습일`이 전부 비어 있었다 — 1·3·7일 주기를 갱신하는 주체가 없다.

즉 **오류는 기억되지만 쓰이지 않는다.** §2의 "해결할 문제" 첫 항목("다음 학습에서 같은 오류가 다시 연습되지 않는다")이 그대로 남아 있다.

### 11.2 요구사항

| # | 요구사항 |
|---|---|
| **R11-1** | 학습자의 오류 이력을 영속 저장한다 — 패턴, 발생 위치와 교정, **교정 후 재발화 시도의 정답 여부**, 발음 시도(§10 R10-2) |
| **R11-2** | 세션마다 "오늘 무엇을 어떻게 연습할지"를 그 이력에서 정한다 — 초점 패턴 **1~2개**, 질문 **3~5개**, 난이도, 추천 이유 |
| **R11-3** | 추천 이유는 **필수**다. 학습자가 화면에서 왜 이 연습인지 확인할 수 있어야 한다(§8 유지) |
| **R11-4** | 계획 생성은 **학습자가 기다리는 경로에 두지 않는다** — 앞선 세션이 끝날 때 비동기로 만들어 둔다(§8 "음성 응답 경로에서 장기 분석을 동기 호출하지 않는다"의 연장) |
| **R11-5** | 계획이 없거나 생성이 실패해도 **학습은 시작된다.** 계획 부재가 학습 중단으로 번역되지 않는다 |
| **R11-6** | 복습 주기 1·3·7일을 실제로 갱신한다. **다시 틀린 패턴은 주기를 되돌린다** — 재발한 패턴을 7일 뒤로 미루면 복습의 의미가 없다 |
| **R11-7** | 난이도는 성공률에 따라 조절하되 **한 번에 한 단계씩만** 이동하고, **하향도 허용**한다 |
| **R11-8** | 만성 약점 판정의 임계값을 제품이 발명하지 않는다 — 조회는 **사실(재발 세션 수·재발 일수·지속 기간·휴면 후 재발)** 을 제공하고 판단은 학습 분석 Agent가 한다 |
| **R11-9** | 발음 시도 이력도 계획 입력에 포함되고, 발음 패턴도 초점 패턴이 될 수 있다 |
| **R11-10** | Agent가 유지하는 **관찰 기록**을 보존한다 — 숫자가 담지 못하는 것(예: "짧은 문장에서는 관사를 붙이는데 문장이 길어지면 빼먹는다"). 덧붙이기만 하고 지우지 않아 되돌릴 수 있다 |

### 11.3 수용 기준

- **AC11-1** Given 복습일이 지난 패턴이 여럿 있을 때, When 계획이 생성되면, Then **그 전부가** 계획 입력에 포함된다. 하나라도 누락되면 실패다.
- **AC11-2** Given 특정 패턴의 재발이 가장 심할 때, When 계획이 생성되면, Then 초점 패턴에 그것이 들어가고 질문 3~5개가 그 패턴을 유발하는 상황을 담으며 **추천 이유가 비어 있지 않다**.
- **AC11-3** Given 계획 생성이 실패했을 때, When 학습자가 학습을 시작하면, Then 폴백으로 정상 시작된다.
- **AC11-4** Given 잘못된 계획(추천 이유 없음 / 질문 수 위반 / 난이도 두 단계 도약)이 산출되면, Then 저장을 거부한다.
- **AC11-5** Given 같은 패턴을 두 세션 연속 틀렸을 때, Then 두 번째 세션의 대화가 첫 세션과 **구별된다** — 이것이 4차수 M계층 기준선을 뒤집는 판정이다.
- **AC11-6** Given 발음 재발화에 반복 실패한 패턴이 있을 때, Then 다음 계획의 초점 패턴에 포함될 수 있다.
