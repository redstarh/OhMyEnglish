두 개의 시간축

실시간 (학습자가 기다린다)

  • 오디오 in/out, 전사, 발음 판정 — 전부 Nova 한 번의 대화 턴 안에서
  • DB 쓰기는 INSERT/UPDATE 1회 수준. 음성 경로를 막지 않는다
  • 발음 기록을 create_task로 띄우지 않는다 — 이벤트를 순차 await해야 판정이 무관한 시도를 닫지 않는다

비동기 (학습자가 기다리지 않는다)

  • 전사문 확정 시 analysis_jobs에 job을 같은 트랜잭션으로 등록
  • 워커가 lease를 잡고 Claude 호출 → 패턴 upsert → frequency 재계산
  • 결과 화면은 그 세션의 job이 전부 terminal일 때만 확정 표시

2026-08-29. 판정 UPDATE가 최신 대답기다림만 보고 판정의 target_form을 버리므로 한 행에 두 값이 어긋날 수 있다. 그래도 술어를 더하지 않는다 — 실물 왕복이 0회라 이 순서가 일어나는 증거가 없고, 문자열 일치는 모델의 미세한 재렌더에 빗나가 "대답 없음" 행을 늘리는 새 실패 모드를 만든다. 빈도는 5차수 관측.

패턴의 target_form → 일반형(소리)

2026-08-29. 처음엔 시범 문장을 넣었으나 코드리뷰가 반박했다 — 스키마 정본이 이 컬럼을 "일반화된 목표 형태, 문장이 아니다"로 정의하고 근거가 관측된 결함이다. 문장은 이미 시도 행에 있다. 문장으로 되돌리지 마라.

수렴값 → incorrect

설계서의 unclear를 뒤집었다. "대답을 못 한 것은 못 한 것"이고 이후 학습도 그냥 틀림으로 본다 — "대답 안 함"만 따로 세는 규칙을 두지 않는다.

agent_reprompt → 만들지 않는다

되묻기 문구 감지는 문구 매칭이라 케이스가 불어나고 지시문이 바뀔 때마다 조용히 깨진다. R10-4의 절반은 의도적 미충족이고 그 크기는 5차수 관측 대상이다.

이 설계가 스스로 인정한 약점

  • 교정 예산이 코드로 강제되지 않는다 — 관측 수단은 있다(세션당 시도 행 수)
  • 판정 품질을 회귀 테스트할 수 없다 — Nova 판정은 비결정적이라 자동 테스트는 "규칙이 전달됐고 스키마가 맞다"까지다
  • 픽스처가 합성음이다 — 원어민 발음이라 한국인의 중간값·불안정성을 재현하지 않는다
  • Task 8이 소리 키를 그대로 렌더하면 학습자가 th_as_s를 본다 — 표시 문구는 별도 결정이 필요하다
